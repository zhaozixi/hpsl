> 决策背景：`_active_pid` 是模块级进程内句柄，重启即清空。M34 补了切换入口后已不至于「项目失联」，
> 但每次重启仍需手点一次切换。用户拍板按 **显式 / 可见 / 可关** 三原则实现恢复，并顺带清掉 M34 遗留的

> 浏览器复验 5/5 通过、13 页控制台零 error。

## 一、核心决策：不新增存储，从既有留痕反推

最初的问题表述是「`_active_pid` 要不要持久化」。读代码后发现**不需要持久化**——数据早就在库里了：

| 事实 | 位置 |
|---|---|
| `_active_pid` 是 `Optional[str] = None` 的模块级变量 | `projects.py:37` |
| `set_active()` 只校验存在 + 赋值，**不写库** | `projects.py:181` |
| 但切换端点为了满足 M1 AC7「切换须留痕」，会写 `config.last_active_at` | `routes/projects.py:86` |
| `uvicorn(workers=1)`，单进程 | `app.py:256` |
| `active_project()` 被 **34 处 / 22 个文件**依赖 | 全站隐式上下文 |

也就是说，`last_active_at` 这个「为审计而写」的副产物，天然就是「上次在哪个项目」的权威记录。
于是恢复做成**只读反推**，而不是引入一个新的可写状态源：

```python
def restore_last_active() -> Optional[ProjectVO]:
    best_pid, best_ts = None, ""
    for vo in list_projects():
        ts = get_raw_config(vo.id).get("last_active_at")   # 只读
        if isinstance(ts, str) and ts > best_ts:
            best_pid, best_ts = vo.id, ts
    if best_pid is None:
        return None                                        # 无记录不猜
    set_active(best_pid)
    return get_project(best_pid)
```

时间戳由 `_switch_ts()` 统一生成（UTC 定长 ISO-8601），因此可直接做字典序比较，无需解析。

**为什么这个设计值得**：单一真相没被破坏——`last_active_at` 的唯一写入点仍然是 switch，
恢复只读不写。测试 `test_restore_is_read_only` 直接断言「config 逐字节不变 + audit_log 不新增」。

## 二、三条原则的落点

### 1）显式（Explicit）

恢复只挂在 `serve()` 里，**绝不在模块导入期执行**：

```python
# serve() 内，库可读之后、uvicorn.run 之前
if restore:
    _restore_active_project()
```

原因很实际：若放 import 期，576 例（现 594 例）测试的 `_active_pid` 会被外部数据目录的
`last_active_at` 左右，隔离性直接破掉。测试文件 `fresh_home` fixture 也据此显式清空句柄。

失败降级：`restore_last_active()` 抛任何异常 → 记 warning、以空态启动，绝不阻断服务。

### 2）可见（Visible）

只恢复不提示＝把隐式状态藏得更深。所以做了一层常驻顶栏：

```
当前项目：学会 SQL 查询优化 · 你的所有操作都记在这个项目里        切换 / 查看全部项目
```

实现走中间件注入 `request.state.active_label`，各路由的 `Jinja2Templates` 一个都不用改：

```python
@app.middleware("http")
async def _inject_active_ctx(request, call_next):
    request.state.active_label = _projects.active_label()   # 读进程内缓存，零额外查库
    return await call_next(request)
```

`active_label` 在 `set_active()` 时一并缓存（`_read_project_row` 本来就返回了 name，不额外查库）。
这条横幅同时把 M34 的「切换入口」永久暴露在所有页面上，不再依赖用户记得回首页。

### 3）可关（Closable）

```bash
hpsl serve --no-restore
HPSL_NO_RESTORE_ACTIVE=1
```

启动日志把三种结果都说清楚，不留悬念：

```
[serve] 已恢复到上次项目：学会 SQL 查询优化（0f29d17c...）
[serve] 已按 HPSL_NO_RESTORE_ACTIVE 跳过恢复上次项目
[serve] 无历史活跃项目记录，以「未选择项目」启动
```

## 三、四项体验债

### E1 · 详情页配置 dump

`<pre>{{ config }}</pre>` 把整坨 JSON 糊在页面上（开发态残留）。改为 9 行中文表格
（通过阈值 / 高低分线 / 缺口上限 / 单次时长 / 零缺口比例 / 强行闭环比例 / 跳过产出比例 /
复测间隔 / 预算上限），原始 JSON 收进 `<details>查看原始配置（排障用）</details>`。

预算维持美元计价并注明口径，没有在模板里硬编码汇率——避免出现第二套换算标准。

### E2 · 错误文案分层

原先 `msg=f"Provider {p} 返回 {status}：{detail}"`，`detail` 是上游英文原文，直接怼到用户脸上：

```
Authentication Fails, Your api key: ****abcd is invalid
```

改法：`BizError` 增可选的 `detail` 字段（默认 `None`，现有调用零影响），上游原文与主提示分离。

```python
_HTTP_HINTS = {
    400: "请求被拒绝（多半是模型名或参数不适用）",
    401: "密钥无效或已失效，请到「设置 → 密钥」重新填写",
    403: "密钥没有访问该模型的权限，请检查账号权限",
    404: "模型或接口地址不存在，请检查模型名是否正确",
    413: "请求内容过大，请缩短输入或减少资料挂载",
    422: "参数不被接受，请检查模型名与请求设置",
}
```

界面效果（实测，假密钥打 DeepSeek）：

```
deepseek 返回 401：密钥无效或已失效，请到「设置 → 密钥」重新填写（A040001）
▸ 技术细节
```

`<details>` 由 `_biz_error_handler` 的 HTMX 分支渲染；**JSON 契约不变**（仍 `code/msg/data/traceId`
四字段），`detail` 不泄漏进 REST 响应。同时清理了 429/5xx 与网络异常两条同类文案
（原 `Provider x 调用失败（重试耗尽）：{httpx 异常}`），`anthropic.py` 的 6 处一并中文化。

### E3 · 建单元反馈

原实现返回 `<p>已创建单元，正在刷新…</p>` + `HX-Refresh: true` —— 整页刷新会立刻把提示冲掉，
用户实际看不到任何确认。改为：

- 结果区：`已创建单元「X」，已加入下方列表。`（`html.escape` 转义标题）
- 列表区：抽 `_unit_list.html` 为唯一实现，响应里带 `hx-swap-oob="true"` 就地替换
  （标题里的计数「单元列表（N）」也跟着更新）
- 表单：就地刷新不会清空输入框（整页刷新时代是被刷新顺手清掉的），补一段 `reset()` + 焦点回到标题，
  避免用户误以为没提交成功而重复点击；`allowScriptEval` 被关闭时只是不清空，无副作用

### E4 · 向导原生校验

三个步骤的输入原本裸放在 `<section>` 里，按钮却是 `type=submit` —— 不在 `form` 内，浏览器不触发
`required`。改为步骤 1/2 各自包一层真 `<form onsubmit="event.preventDefault(); stepXxx();">`，
补 `required` 与 `maxlength`（名称 200 / 目标 500 / 初始认识 2000 / 密钥必填 + `autocomplete="off"`）。
JS 里的 `if (!name || !goal)` 保留作为 trim 兜底（`required` 拦不住「全是空格」）。

## 五、残留与已知取舍

1. **原生校验提示的语言跟随浏览器 UI locale**，不受页面 `lang="zh-CN"` 控制。实测 Chromium
   默认 en-US 时提示为 `Please fill out this field.`；中文系统上即为中文。这是原生行为，不再重造轮子。
2. **恢复是单实例语义**：两个进程共用同一 `HPSL_HOME` 时，「上次」会互相抢占。本地单用户工具可接受，
   需要严格隔离时用 `--no-restore`。
3. **项目被删后顶栏可能短暂显示旧名**（`_active_label` 是缓存）：`active_project()` 仍会返回 `None`，
   业务不受影响；重启即自愈。
4. **`/settings` 仍有一处配置编辑入口**，与详情页的只读表格职责不同，未合并（避免扩大范围）。
