## 3. 缺陷清单与定级

### D-M2-1（历史缺陷，本次确认已闭环）

| 项 | 内容 |
|---|---|
| 标题 | 复测后 review 行被置失活，导致 2/7/21 循环断裂 |
| 严重级别 | **严重（修复前）** → 现 **已闭环** |
| 根因 | `submit_review` 曾将 `review.result` 写为"通过/未通过"，使 `due_reviews` 的 `result IS NULL` 过滤永久失活该活跃行，循环断裂 |
| 修复 | 保持 review 活跃（`result` 维持 NULL）+ 仅推进 `due`；复测结果以 `attempt(kind='复测')` 为准 |
| 独立验证 | C7 + test_review_interval_cycling：独立复现 2→7→21→21 全程触发，**每次 `review.result` 恒 NULL、活跃行恒 1**；`_next_interval` 映射正确 |
| 结论 | **闭环确认**。修复有效，D-M2-1 不再复现 |

### O-M2-1（新发现，观察项，定级：一般 / 建议澄清）

| 项 | 内容 |
|---|---|
| 标题 | `LEARN→VERIFY` 直接跳过 PRODUCE 路径不被支持（与任务书 B 项期望不一致） |
| 严重级别 | **一般**（不违反任何正式 AC-M2-1~8；AC-M2-2/3 已由 `PRODUCE→VERIFY` 覆盖） |
| 现象 | 任务书 B 项明确要求：直接 `LEARN→VERIFY` 无 reason → A020003；带 reason → skipped_produce=1 且 status=VERIFY。实测两者均返回 **A020001**（status 不变、skipped_produce 未置） |
| 根因（规格内部不一致） | ① 需求基线 §4.1 迁移表 `TRANSITIONS[LEARN]=(PRODUCE, PICK)`，**未列 VERIFY**；② 但同节 PRODUCE 闸门注记又称"凡进入 VERIFY 的转移（PRODUCE→VERIFY，**含 LEARN→VERIFY 直接跳过的异常路径**）"——自相矛盾；③ 任务书 B 项直接以 LEARN→VERIFY 为合法闸门路径 |
| 实现行为 | 实现严格对齐迁移表：合法性校验（`nxt ∉ TRANSITIONS[cur]`）先于闸门触发，故 `LEARN→VERIFY` 在合法性处即抛 A020001，**闸门内的 A020003/skipped_produce 分支对 LEARN→VERIFY 不可达** |
| 影响面 | 若 M10 Web 暴露 `LEARN→VERIFY` 入口（"跳过产出直接进入验证"），将得 A020001 而非预期的 A020003/放行 |
| 定级理由 | 非致命/严重：正式验收条款未要求此边；但属主理人点名验证项且规格自相矛盾，须澄清 |
| 修复建议（供主理人裁决） | **(a)** 若产品确有"跳过产出直接验证"意图：在 `TRANSITIONS[LEARN]` 增补 `VERIFY`（闸门代码已能正确处理该边 → 即得 A020003/skipped_produce=1），最贴合任务书 B 项预期；**(b)** 若不支持该边：在需求基线 §4.1 明确"LEARN→VERIFY 不支持"，并同步修订 PRODUCE 闸门注记与任务书 |

### O-M2-2（新发现，观察项，定级：轻微 / 文档一致性）

| 项 | 内容 |
|---|---|
| 标题 | 锁定基线 §3.2.M6.5 与需求基线 D-M2-1 修复冲突（review.result 处置） |
| 严重级别 | **轻微**（实现无缺陷，纯文档一致性） |
| 现象 | 锁定基线 `系统设计.md` §3.2.M6.5 第 1787 行规定"更新 review：result = 通过/未通过"，第 1805 行写回四类落点含 `review.result`；与需求基线 §4.2/§6 的 D-M2-1 修复（review.result 维持 NULL、仅推进 due）直接冲突 |
| 实现行为 | 实现遵循**权威需求基线**（result 恒 NULL），行为正确 |
| 风险 | 锁定基线文档未同步，后续维护者/审计易误读为缺陷 |
| 建议 | 主理人择机将锁定基线 §3.2.M6.5 该处修订为"review 保持活跃、result 维持 NULL、仅推进 due"，与需求基线对齐 |

### O-M2-3（新发现，观察项，定级：轻微 / 健壮性强健性）

| 项 | 内容 |
|---|---|
| 标题 | 复测间隔推进依赖 `(due - last_verified_at)` 推导，非显式阶段计数 |
| 严重级别 | **轻微**（主链路 AC 用例均用全新概念，未覆盖此边，不影响验收） |
| 现象 | `_interval_days(due, lva)=round((due-lva).days)`，首档间隔由 `lva` 决定：全新概念 lva=NULL→首档 2(→7→21→21) 正确；但若概念 `last_verified_at` 与入队时间相差较远（如重入队一个很早验证过的概念），首档可能直接跳到 21，偏离"严格逐档 2→7→21"直觉 |
| 实现行为 | 规范路径（C7）已验证正确，符合需求基线"2→7→21→21"语义 |
| 建议 | 若需严格逐档推进，改为显式阶段计数（或约束 lva 与入队时间差）；否则在规格中明确"间隔由 (due-lva) 推导"的语义，避免歧义 |

## 4. 质量结论

### **结论：有条件通过（Pass with Conditions）**

**通过依据（满足度）：**
- AC-M2-1~8 **全部满足**，对应 18 个 M2 用例全绿；
- 全量 63 用例 0 失败，M0/M1 回归 45 绿（AC-M2-8）；
- 历史严重缺陷 **D-M2-1 已闭环**，独立复现 2→7→21→21 循环全程有效、`review.result` 恒 NULL；
- 写回隔离不变量（unit/gap 零写入）、headless（无 routes/app 依赖）、db.write 白名单与"绝不直写 audit_log"均经独立 AST/运行时校验确认；
- 无 致命 / 严重 级未闭环缺陷。

**条件（发布前须主理人裁决）：**
- **条件 1（来自 O-M2-1）**：`LEARN→VERIFY` 直接跳过 PRODUCE 路径的规格自相矛盾（迁移表 vs 闸门注记 vs 任务书 B 项）。**在 M10 Web 暴露该入口前，主理人须裁定**：增补迁移边（方案 a）或在规格中明确不支持并同步修订（方案 b）。本引擎层当前行为（拒绝为 A020001）对照迁移表可辩护，但不符合任务书 B 项明示期望。
- **条件 2（来自 O-M2-2 / O-M2-3）**：为降低后续维护/审计误读，建议择机同步锁定基线 §3.2.M6.5 的 review.result 描述，并明确复测间隔推导语义。二者均为文档级，不阻塞引擎发布。

> 若主理人确认 O-M2-1 采用"方案 b（不支持该边）"且同步修订规格，则本 M2 可转为**无条件下通过**。
