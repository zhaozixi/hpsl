## 3. 本轮发现与处置

### F-01【P1，已修复】E2E 在中文 Windows 上必然失败

- 现象：`HPSL_E2E=1 pytest tests/e2e` 失败，报「缺少预期步骤」，实际 node 子进程 stdout 为空。
- 根因：`subprocess.run(..., text=True)` / `Popen(..., text=True)` 用系统 locale（GBK）解码；
  node 与 uvicorn 输出 UTF-8 中文 → 读取线程 `UnicodeDecodeError`，`stdout` 变空。
- 修复：三处子进程统一 `encoding="utf-8", errors="replace"`
  （`tests/e2e/conftest.py` 服务 Popen、node 探针；`tests/e2e/test_project_lifecycle.py` 剧本 run）。
- 复验：E2E **1 passed / 26.05s**；默认全量不受影响。

### F-02【P2】健康标记停在 M36

`/healthz`、`/readyz` 仍返回 `phase: "M36"`（`app.py:159,171`），而项目已到 M40。
不是功能缺陷，但监控/排障会误判版本。建议改为 `phase: "M40"` 或直接返回 `version`。

### F-03【P2】REF-1/REF-2/REF-3 停在 10-18（M36）

三份 `docs/REF-*.md` 的最后修改时间仍是 2026-10-18，内容为 692 passed / M36；
M37–M40 的能力、路由数（74/18）、测试数（754/4）均未回填。README/ROADMAP 已更新到 M40，
形成「一处新、三处旧」的口径分裂。建议做一次 REF 合并回填（可并入下一批文档债）。

### F-04【P2】归档项目仍可通过 API/旧链接切换

`POST /api/v1/projects/{pid}/switch` 只校验项目存在，不检查 `archived_at`；
页面已隐藏归档项的切换按钮，但直接调用 API 或旧 URL 仍可把归档项目设为 active。
后果：顶栏显示一个归档项目、`/unit` 等页面可继续操作它，「归档」语义被绕过。
建议在 `switch_api` 对归档项目返回 A010001（或明确允许并写文档二选一）。

### F-05【P3】删除确认的「逐字」被 `strip()` 放宽

`projects.delete_project` 用 `confirm_name.strip() != expect`，允许首尾空格；
文档写「逐字一致」。影响很小，但属于文档与实现口径差。

### F-06【P3】极小人民币金额会显示为 `¥0.0000`

`money._cny_digits` 对 <0.01 固定 4 位；当 USD 费用 <约 0.0000069 时折算显示 `¥0.0000`。
文档声称「小额不会变成 ¥0.00」，严格说只对 ≥0.00005 USD 成立。
建议 <0.0001 时用 6 位，或直接显示 `<¥0.0001`。

### F-07【P3】trash 只增不减；E2E 只覆盖项目生命周期

- `HPSL_HOME/trash/` 无自动清理（M40 文档明确是取舍），长期使用需用户手动清；
- E2E 仅一条「项目生命周期」剧本，密钥页、单元主链、归档后的备份覆盖尚无浏览器用例；
- E2E 默认 skip 意味着 CI 里默认不跑浏览器（设计如此，但发布前应显式跑一次）。

### F-08【P3】`provider_has_key` 吞掉所有异常

`registry.provider_has_key` 用 `except Exception: return False`；密钥库损坏/权限错误
会表现成「没配置密钥」，用户被引导去重填，而不是看到真实错误。建议至少记日志。
