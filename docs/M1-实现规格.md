## 1. M1 目标与定位

M1 = 基线 F1 的 Web 接入部分 + 冻结项 #5 安全基线落地 + **D1 缺陷闭环**。把 M0 的 `projects.py` 内部 API 暴露为 HTTP 接口，提供最小 HTMX/Jinja2 页面（首页/建项向导/项目详情/配置），并落地本地安全边界（Host 白名单 + 写请求 Origin/CSRF 双提交 + safe_path + 五维限流）。

**与 M0 的衔接决策（已裁决，必须沿用）**：`project` 表无 `name` 列，`name` 持久化于 `project.config` JSON 的 `name` 键；`ProjectVO.name` 由 config 还原；项目名唯一性在创建时扫描各项目目录读 `config.name` 判定。M1 接口层对 `name` 透明处理。

## 2. 范围边界

### 2.1 In-Scope（M1 必须交付）

1. **D1 闭环（硬前置）**：`db.py` 给每个 pid 的写路径加 `threading.Lock`（写连接单例 + 锁），消除 uvicorn 线程池并发写导致的 cursor 交错 / 嵌套 BEGIN 的 SQLITE_BUSY。所有 `write()`/`undo()` 经此锁。
2. **HTTP 路由层**（FastAPI，uvicorn 单 worker，127.0.0.1:8765 可配）：实现 §3.2.M1.2 的 7 个接口 + `/api/v1/projects/{pid}/backup` 占位（返回 501 或最小骨架，完整快照轮转留 F1）。
   - `POST /api/v1/projects`（创建，建目录 0700→迁移→写 project 行）
   - `GET /api/v1/projects`（列表）
   - `POST /api/v1/projects/{pid}/switch`（切换 active）
   - `GET /api/v1/projects/{pid}`（详情，含初版认识）
   - `PUT /api/v1/projects/{pid}/initial-belief`（录入/更新初版认识）
   - `GET /api/v1/projects/{pid}/config`（读生效配置，全局+覆盖合并）
   - `PUT /api/v1/projects/{pid}/config`（更新项目级阈值覆盖，经审计）
3. **最小前端**：Jinja2 模板 + HTMX 局部更新——首页（项目列表 + 新建入口）、建项向导（name/goal/initial_belief）、项目详情（初版认识 + 配置）。风格从简，不作视觉设计（UI 角色未参与 M1）。
4. **安全基线（冻结项 #5，本地等效）**：
   - Host 白名单校验（可配置，默认 `127.0.0.1`/`localhost`）→ 非白名单 Host 返回 400。
   - 写请求（POST/PUT/DELETE）Origin 校验（scheme://host 须为回环）→ 不符 403。
   - CSRF 双提交：GET 下发 CSRF cookie（可读，供 JS/HTMX 取用）+ 写请求须带 `X-CSRF-Token` 头且值等于 cookie → 缺失/不符 403。HTMX 通过 `<meta>` + `hx-headers` 或 JS 注入头。
   - safe_path：任何基于 pid/路径的文件访问必须落在 `HPSL_HOME/projects/{pid}/` 内，越界返回拒绝（C400002，M0 已实现 safe_path 函数，接入路由层）。
   - 五维限流（50/20/10/2/5）：实现进程内基础限流器（单进程足够），阈值取自 config，越限 429；详细调参与 `test_security` 拒绝率 100% 留 M10 收口。
5. **错误码**：沿用 M0 `common/errors.py` 的 6 位体系（A010002 重名 / B999001 / B999002 / C400002 / A070001 / A070002 等），新增 Web 层错误（如 A020001 Host 不在白名单 / A020002 CSRF 不符 / A020003 Origin 不符 / A020004 限流）并入注册表。

## 5. 安全基线实现要点（冻结项 #5）

| 机制 | 实现 | 拒绝/异常 |
|---|------|----------|
| Host 白名单 | `config.py` 配置 `ALLOWED_HOSTS`（默认 `["127.0.0.1","localhost"]`）；FastAPI 中间件取 `Host` 头，不在列表→400 A020001 | 非白名单 Host |
| Origin 校验（写） | 写请求依赖读 `Origin` 头，解析为 scheme://netloc 须∈回环（127.0.0.1/localhost）→ 403 A020003 | 写请求 Origin 非回环/缺失 |
| CSRF 双提交 | GET 经依赖下发 `csrf_token` cookie（随机 32B hex，可 JS 读）；写请求依赖校验 `X-CSRF-Token` == cookie 值→ 403 A020002 | 缺失/不符 |
| safe_path | 路由层凡涉及 pid/路径访问先 `db.safe_path(pid, rel)` 解析并校验前缀→越界 C400002 | 目录穿越 |
| 五维限流 | 进程内令牌桶/滑动窗口，阈值 (50/20/10/2/5) 来自 config；越限 429 | 超限 |

> 说明：以上为 M1 落地机制；`test_security` 的「拒绝率 100%」全量断言与精细调参在 M10 收口（基线 §11）。

## 7. 实现注意

- **不引入 ORM**：SQL 全部手写，沿用 M0 `db.write` 唯一写入入口；业务代码不得直写 audit_log。
- **单写连接 + 锁**：D1 闭环后，写连接单例 + `threading.Lock` 双重保证串行；读连接仍多连接。
- **CSRF 与 HTMX**：用 `<meta name="csrf-token" content="...">` + 一小段 JS 在 `htmx:configRequest` 事件中把 token 注入 `X-CSRF-Token` 头；或表单隐藏域 + `hx-headers`。M0 已无前端，M1 新增。
- **HTMX 来源**：优先 CDN（如 `https://unpkg.com/htmx.org@1.9.x`）；若需离线，拷贝到 `static/`（实现时按环境决定，默认 CDN + 注释说明离线降级）。
- **错误码注册**：新增 A020001/A020002/A020003/A020004 等进 `common/errors.py` 注册表。
- **不改动基线文档**：实现只在新目录/文件，不碰 `.workbuddy/delivery/`。
