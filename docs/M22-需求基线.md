## 0. 背景与诉求

M11 批次1 的向导第 2 步「填写模型密钥」仅暴露 `openai_compat` 与 `anthropic` 两个 Provider；
`deepseek-chat` 虽列于 `models.yaml`，但其 `provider` 同为 `openai_compat`，默认 `base_url` 仍指向
`https://api.openai.com/v1`——**实际连不到 DeepSeek**。国内主流大模型（DeepSeek / 通义千问 / 智谱 GLM /
Moonshot(Kimi) / 豆包）在既有的「Provider 下拉 + 密钥存储 + 连通性测试」链路上**完全不可配**。

用户指令（原话）：**「第 2 步 · 填写模型密钥 配置常见的国内外大模型」**。

诉求：把常见国内外大模型做成**各自独立 Provider**（各自 `base_url`、密钥分别存储、连通性分别可测），
使向导第 2 步下拉、设置页密钥存储、连通性测试三处统一覆盖。

## 2. 设计要点

### 2.1 引入 `kind`（接入协议类别），与 `provider`（厂商身份）解耦
- `provider` = 厂商唯一身份（密钥存储槽、连通性测试目标、向导下拉项）。
- `kind` ∈ {`openai_compat`, `anthropic`, `gemini`} = 接入协议；决定适配器构造与探活分支。
- 国内厂商（DeepSeek / 通义 / 智谱 / Kimi / 豆包）均为 **OpenAI 兼容协议** → `kind=openai_compat`，
  复用既有 `OpenAICompatAdapter` + Bearer 探活，**无需新增路由分支**。

### 2.2 `models.yaml` 字段扩展
每个 provider 声明：
```yaml
providers:
  deepseek:
    display: DeepSeek（深度求索）
    kind: openai_compat
    base_url: https://api.deepseek.com/v1
```
OpenAI 厂商 id 由 `openai_compat` 重命名为 `openai`（语义更准）；新增 `gemini` 及 5 个国内厂商。

### 2.3 路由改造（按 kind，非字面 provider）
- `registry.default_base_url(provider)`：优先读 YAML `base_url`，兜底回退。
- `registry.provider_kind(provider)`：新增，返回 `kind`（缺省 `openai_compat`）。
- `registry.build_adapter`：先取 `kind = provider_kind(...)`，再按 `kind` 分流（anthropic → `AnthropicAdapter`、
  gemini → `GeminiAdapter`、默认 → `OpenAICompatAdapter`）。
- `connectivity.test_connection`：按 `provider_kind` 分流探活（Bearer / x-api-key / key 参数）。

### 2.4 保留约束（硬）
- `deepseek-chat` 保留 `family: deepseek, derived_from: gpt4o`（同源判定测试 `test_models`/`test_claim_check` 依赖）。
- `gpt-4o-mini` / `claude-3-5-haiku-20241022` 模型 id 不变（`build_adapter` 测试依赖）。
- 零 DDL、密钥红线（不进 project.db / 脱敏 / 不随导出）、安全分层（读/写）、错误码分段复用、
  引擎 headless 不变、`app.py` 中间件顺序（Security 在内、TraceId 在外）不变。

## 4. 偏差与决策

- **D-M22-1**：provider 重命名 `openai_compat`→`openai`。波及 3 个测试文件（`test_models`/`test_web_m11`/`test_cost`）
  的机械 `openai_compat`→`openai` 改名（含密钥槽名、向导下拉断言、cost 派生 provider、种子数据），属预期重构。
- **D-M22-2**：`kind` 与 `provider` 解耦，避免「每加一个厂商就要改路由分支」的脆弱模式（M11 旧实现按字面
  `provider == "openai_compat"` 硬编码，新增厂商必漏分支）。
- **D-M22-3**：`_DEFAULT_BASE_URLS` 清空为 `{}`，base_url 以 YAML 为单一事实来源（兜底仅防未知 provider）。
