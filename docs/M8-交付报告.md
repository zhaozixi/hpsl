## 2. 范围与边界

### 2.1 In-Scope 已交付
1. **调用记账 `record_call(role, reply, session_id, unit_id) -> CostEstimateVO`**：记一行 llm_call（actor=system，经 db.write 同事务审计）；provider 由 model 经 registry 推导；tokens 由 raw.usage 兼容归一化（OpenAI/Anthropic）；cost 按 pricing.yaml 计算（未登记模型记 0.0）；返回会话估算。
2. **会话花费估算 `session_cost(session_id) -> CostEstimateVO`**：会话级 tokens/cost 聚合 + 当月累计（跨会话，UTC 自然月）+ 预算上限 + 三态 + confirmations + computed_at。
3. **预算三态 `budget_status(session_id) -> str`**：ok（<80%×cap）/ warn（80%~100%）/ blocked（≥100%）读时判定；M4 闸门消费。
4. **超限确认 `confirm_continue(session_id, actor='user') -> CostEstimateVO`**：写审计留痕（db.append_audit_event，table_name='cost_confirm'）+ 本会话放行（blocked→warn）；confirmations 由 audit_log 派生。
5. **DTO/VO（`common/dto.py`）**：`CostEstimateVO` / `CostConfirmRequest`。
6. **错误码（`common/errors.py`）**：新增 `A080002`（成本模块未激活项目）。
7. **审计事件写入（`db.py`）**：新增 `append_audit_event`（受控直写 audit_log，零 DDL）。
8. **导出补齐**：`engine/__init__.py` 导出 `record_call` / `session_cost` / `budget_status` / `confirm_continue`。
9. **测试**：`tests/test_cost.py`（17 例：记账/OpenAI·Anthropic 兼容/未知模型/聚合 ok/warn/blocked/确认放行+审计/多次确认累加/跨会话累计/跨月隔离/三态边界 warn@80%/blocked@100%/未激活 A080002/非法 actor/缺 raw 防御/FK 强制/clerk actor）。

### 2.2 Out-of-Scope（留待后续，未做）
- HTTP 路由（/api/v1/sessions/{sid}/cost、/api/v1/cost/monthly、/api/v1/sessions/{sid}/cost/confirm、/api/v1/settings/budget）属 M10；`CostConfirmRequest`（acknowledged 恒 true）为 M10 REST 入参。
- M4 闸门升 A080001 的接线（blocked → 抛 A080001 → 弹层 → confirm_continue）属 M4/M10 范围；M8 仅提供 `budget_status` 三态判定与 `confirm_continue` 放行原语。
- `CostBreakdownVO`（当月按角色/模型拆分）属 M10 的 /api/v1/cost/monthly 响应；M8 内部 API 仅提供跨会话当月累计聚合。
- M4 适配器 `_on_call` 钩子接 `record_call` 属 M4 范围；M8 保证 `record_call` 可重复调用（每调用独立记一行）。

## 3. 与锁定基线的偏差与实现决策（须记录）

| # | 偏差/决策 | 原因 | 处理 | 影响 |
|---|-----------|------|------|------|
| D-M8-1 | `confirm_continue` 经 `db.append_audit_event` 直写 audit_log | §3.2.M8.4 序列图显式要求写 audit_log；超限确认无业务行可写 | M0 纪律「audit_log 仅由 write() 内部追加」被有意放宽，但 `append_audit_event` 仍集中在 `db` 模块、只写纯审计事件（无业务表写入），不新增表/列，零 DDL | 16 库对象锁定不被破坏 |
| D-M8-2 | 内部 API 签名锁定不含 pid，依赖激活项目上下文 | §3.2.M8.2 字面签名如此；跨项目会话查询不可能 | pid 经 `projects.active_project()` 解析；未激活 → A080002 | 严格对齐锁定基线 |
| D-M8-3 | provider 由 model 经 registry 推导；未知模型 provider='unknown'、cost=0.0 | 已核实适配器 `Reply.raw=data`（上游响应）不含 provider 键 | `registry.get_model(model).provider`；缺价降级不计入预算 | 不破坏 Reply 契约 |
| D-M8-4 | `input_hash` 由 角色+模型+回复签名 派生（record_call 未持请求体） | 签名锁定不含请求体；uk 索引含微秒 ts 防碰撞 | `_input_hash` = sha256 | 幂等索引有效 |
| D-M8-5 | blocked 且 confirmations≥1 → warn（本会话放行）；A080001 由 M4 升 | 状态机 §3.2.M8.5；零 DDL 下不能新增会话状态列 | confirmations 由 audit_log 计数派生；放行以审计为依据 | 读时计算，无持久状态 |
| D-M8-6 | record_call 前置：session/unit 业务行须已存在（FK） | llm_call 外键约束；M4 调用前必已建 | M8 不自动建；测试预建 | 单一写入口纪律 |

> 以上偏差均不破坏 M0 锁定的 16 库对象（零 DDL 已实测验证）。
