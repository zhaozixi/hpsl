## 1. M7 目标与定位

M7 = 锁定基线 **§3.2.M7 四本账与审计模块（BC-5）** 的后端编排层落地。

**范围边界（关键澄清）**：
- M0 的 `db.py` 已实现四本账的**底层写入与审计基座**：`write(pid, table, row, actor)`（白名单校验 + 同事务审计）与 `undo(pid, audit_id, actor, expected_prev_hash)`（旧值指纹校验回滚，A070001/A070002 已注册）。因此 M7 **不再重造 write/undo**，而是在其上增量实现四本账**编排语义**。
- M7 NEW = `confirm_gap_candidates`（候选缺口批量确认入账/废弃）、`list_gaps`（缺口账本查询）、`ledger_summary`（四本账统计摘要）；以及 §3.2.M7.3 的 DTO/VO（落 `common/dto.py`）。
- F2「四本账与审计」在基线中多处被标注为 M0–M2（存储/审计基座），而 §3.2.M7 单列本里程碑做**编排层与语义收口**；M7 与 M0 的关系是「基座 + 编排」分层，不冲突。

**承接已核实资产（必须沿用）**：
- `db.write`（M0）：白名单 + 同事务审计，所有账本写入唯一入口；`db.undo`（M0）：A070001（审计不存在）/ A070002（旧值指纹不匹配）回滚。
- `errors.py` 已注册 `A070001` / `A070002` / `B999001` / `B999002`；M7 错误码空间（A07xx）已齐备，**无需新增错误码**。
- 纪律红线（全程沿用）：密钥红线（D1 §6.5）、隔离红线（O13）、错误码分段（M7 = A07xx）、**零 DDL**（M0 锁定的 16 库对象中 gap/gap_candidate/audit_log 等已含 M7 所需列）、headless 不依赖 routes/app、`write` 唯一写入口。

## 2. 范围边界

### 2.1 In-Scope（M7 必须交付）

1. **候选缺口批量确认 `confirm_gap_candidates(pid, items, actor='user')`（§3.2.M7.2 内部 API）`engine/ledger.py`**
   - items 每项 `{candidate_id, action, level}`；action ∈ {confirm, discard}。
   - confirm：写 `gap`（level=确认等级，缺省取候选 `suggested_level`；status=待补；actor=user）+ 候选置「已确认」。
   - discard：候选置「废弃」。
   - 幂等（候选 ID 集合）：已确认/已废弃候选跳过；缺失候选安全跳过（重放安全）。
   - 非法 action → `C400001`；confirm 等级非 1/2/3 → `C400001`。
   - 会话收尾（§3.2.M7.5 Step 3）：确认/废弃后按候选所属 unit 关联会话，置 `session.gaps_confirmed=1`（M9 零缺口占比分母口径；幂等，重复置 1 无害），经 `_session_ids_for_unit` + `db.write("session", ...)`。
   - 返回 `{confirmed, discarded, skipped}` 计数。
   - 所有写经 `db.write`（同事务审计）。
2. **缺口账本查询 `list_gaps(pid, unit_id=None, level=None, status=None)`（§3.2.M7.2）**
   - 可选过滤返回 `list[GapListVO]`（VO 落 `common/dto.py`）。
3. **四本账统计摘要 `ledger_summary(pid) -> dict`（§3.2.M7.2）**
   - 返回 gaps/units/cards/concept_edges/concepts/reviews_active 计数（选题用，不暴露原始对话）；供 M2 选题与 M9/M10 复用。
   - `_count_by_status` 带白名单断言（表/列名来自代码常量，防注入 T-06）。
4. **DTO/VO（`common/dto.py`）**：`AuditEntryVO` / `GapConfirmRequest` / `UndoRequest` / `CardCreateRequest` / `GapListVO`（§3.2.M7.3）。
5. **导出补齐**：`engine/__init__.py` 导出 `confirm_gap_candidates` / `list_gaps` / `ledger_summary`。
6. **测试**：`tests/test_ledger.py`（10 例，覆盖确认/丢弃/幂等/非法/过滤/摘要/undo 集成）。
7. **回归**：M0–M6 既有 **145** 测试仍全绿（零 DDL、零破坏）。

### 2.2 Out-of-Scope（M7 不做，留待后续）

- **HTTP 路由暴露**（/api/v1/ledger/*、/api/v1/gap-candidates/confirm、/api/v1/audit/{aid}/undo、/api/v1/cards、/api/v1/concept-edges）属 M10 Web 接入；M7 仅落地引擎原语与 DTO。
- **卡片建卡 / 概念图写边**的 UI 编排：写卡经 `db.write("card", ...)`、写边经 `db.write("concept_edge", ...)` 已是 M0 原语；`CardCreateRequest`/`ConceptEdgeRequest` DTO 已定义，但表单交互与句式解析属 M10。
- **备份导出（Markdown）**：属 M10（AC-7.1），M7 提供 `ledger_summary` 统计供其消费，不实现导出本身。
- **四平面阈值面板与周盘点界面**：属 v1（M7 排期标签），M7 仅提供底层统计。

## 3. 与锁定基线的偏差与实现决策（须记录）

| # | 偏差/决策 | 原因 | 处理 | 影响 |
|---|-----------|------|------|------|
| D-M7-1 | 确认入账时 `gap.session_id` 置 NULL | 候选缺口（`gap_candidate`）不直接携带 session；缺口归单元，session 留空 | 确认写 gap 时 `session_id=None`；M10 接入时可回溯 unit→session 回填 | 无 DDL；FK 允许 NULL；不影响统计 |
| D-M7-2 | 非法 action / 等级校验复用 `C400001`（非新增 A07xx 码） | 基线 §3.2.M7 错误码空间仅分配 A070001/A070002（已由 M0 注册）；新增码会越出基线表 | 参数校验类错误统一用 `C400001`（客户端参数错误语义） | 不污染错误码表；与 M1 C400001 一致 |
| D-M7-3 | `gap_candidate.status` 扩展取值「已确认」 | 幂等需要标记已消费候选；schema 列 DEFAULT '待确认' 但为自由 TEXT，无约束 | 确认后置候选 status='已确认'（与 '待确认'/'废弃' 并列）；不改列定义 | 零 DDL；纯值约定 |
| D-M7-4 | `write` / `undo` 不复刻，直接复用 M0 `db.py` | 基线 §3.2.M7.2 内部 API 列 `write(db, table, row, actor)` / `undo(audit_id, actor)`，与 M0 db.write/db.undo 一一对应且已含审计+指纹回滚 | M7 仅在 `db.write`/`db.undo` 之上做编排（confirm/list/summary）；undo 集成测试验证 M7 写路径可回滚 | 严格单一写入口纪律；零 DDL |
| D-M7-5 | 确认后标记 `session.gaps_confirmed=1`（§3.2.M7.5 Step 3） | 独立验证 Agent 指出该 M9 分母口径原未在 M7 实现；主理人补 `_session_ids_for_unit` + confirm/discard 后按 unit 归属会话置 1 | 经 `db.write("session", ...)` 同事务审计；幂等 | 零 DDL；对齐基线流程 |
| D-M7-6 | DTO 形状与基线 §3.2.M7.3 字面不完全一致（AuditEntryVO.id/UndoRequest.audit_id 实码 int 匹配 audit_log.id INTEGER；GapConfirmRequest 实码单条三字段、ledger 以 list[dict] 批量入参；GapListVO/CardCreateRequest 已定义供 M10） | 功能不受影响（M7 内部以 dict 运转） | 属文档漂移非缺陷；M10 接入时与实码对齐 | 已在交付报告登记 |

> 以上偏差均不触及 `db.py` / `routes/` / `app.py` 既有逻辑与 M0 锁定的 16 库对象（零 DDL）。
