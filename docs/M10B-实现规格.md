## 1. 第一批范围

### 1.1 `/settings` 配置页
- 新增 `hpsl/templates/settings.html`（extends `base.html`）：渲染当前激活项目的生效配置表单（字段见 §1.3），htmx `PUT` 至既有 `PUT /api/v1/projects/{pid}/config`。
- 新增页面路由（建议放在 `routes/projects.py` 的 `page_router`）：`GET /settings` → `read_security`；无激活项目 → 渲染带「尚未选择项目」提示（与 `/ledger` 一致）。context：`project`（active.to_dict）、`config`（get_effective_config(pid).to_dict()）。
- `hpsl/templates/base.html` header 增加「设置」链接（`/settings`，依赖 active_project，与现有「项目管理」一致）。
- **不新增后端 API**：复用 M1 既有 config 端点。仅前端模板 + 页面路由。

### 1.2 软提示关闭持久化（替代进程内 `_dismissed`）
- 废弃 `routes/governance.py` 的进程内 `_dismissed: dict[str, set[str]]` 与 `hpsl_sid` cookie 机制（重启清空、跨浏览器失效）。
- 持久化：已关闭软提示 id 存于**项目 config JSON 的 `dismissed_prompts`（list[str]，extra 键，ConfigVO 忽略）**。零 DDL。
- `hpsl/projects.py` 新增 `get_raw_config(pid) -> dict`：返回原始 project.config dict（含 extra 键如 `dismissed_prompts`、M1 写入的 `last_active_at`）。实现参考既有 `_read_project_row` + 其 `config` 键。
- `hpsl/routes/governance.py` 改造：
  - `POST /api/v1/soft-prompts/{id}/dismiss`：读 `get_raw_config(pid).get("dismissed_prompts", [])`，追加 id，`proj.set_config(pid, {"dismissed_prompts": sorted(set(...))}, actor="user")` 持久化（经 `db.write` + 审计）。
  - `GET /api/v1/soft-prompts` 与 `_active_signals(pid, ...)`：过滤依据改为 `set(proj.get_raw_config(pid).get("dismissed_prompts", []))`。
  - 移除 `_dismissed` / `_sid` / `SID_COOKIE` / `_json_ok` 中的 cookie 逻辑（或保留 `_json_ok` 仅返回 JSON，去掉 set_cookie）。
- `hpsl/routes/ledger.py`：过滤改读 `proj.get_raw_config(pid).get("dismissed_prompts", [])`，**不再 import `_dismissed`/`SID_COOKIE`**（消除跨路由进程内状态耦合）。
- 行为变化：v0 由「按会话进程内存」升级为「按项目持久化」——关闭一次，该项目所有会话均不再展示（更合理）。

### 1.3 配置表单字段（复用 `ConfigVO` 已知键）
`pass_threshold`(float)、`pass_hi`(float)、`pass_lo`(float)、`l1_gap_limit`(int)、`session_minutes`(int)、`zero_gap_max`(float)、`forced_close_max`(float)、`skipped_produce_max`(float)、`budget_cap_usd`(float)、`review_intervals`(tuple，UI 以逗号分隔输入，提交时转为 list[int])。

前端提交须发送 **JSON 且类型正确**（数字为 Number、review_intervals 为 int 数组）——因 `ConfigVO.from_dict` 不做字符串强制转换，`set_config` 直接合并。htmx 提交时用少量 JS 读取表单字段并 `JSON.stringify` 构造 body，`hx-headers` 设 `Content-Type: application/json`。

## 2. 纪律约束（必须守住）

- **零 DDL**：不得新增表/列/索引；持久化只用 `project.config` 现有 JSON 列的 extra 键。
- **写唯一入口**：所有写经 `proj.set_config` → `db.write`（含审计）；不得直写 `audit_log`/原生 SQL。
- **错误码**：复用既有（`C400001` 参数非法、`A010001` 无激活项目等）；无新码空间。
- **安全**：页面 GET 用 `read_security`；`PUT`/dismiss 用 `write_security`（Origin + CSRF + 限流）。
- **headless**：engine 层不依赖 routes/app（本批次不改 engine）。
- **复审守护**：`tests/test_governance.py::test_governance_zero_ddl` 断言 `count_user_objects == 16` 必须仍通过。
