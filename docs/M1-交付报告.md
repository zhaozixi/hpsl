## 3. 三项冲突/提报裁决与落实确认

- **(1) 错误码冲突（A020001/2/3 vs C403001）**：M1 规格 §2.1/§5 计划新增 `A020001`（Host）/ `A020002`（CSRF）/ `A020003`（Origin）等 A02xx 码。但锁定基线 §3.5.1 已将这些 A02xx 码**分配给 M2 状态机**，不可触碰。为实现"不破坏基线"的硬约束，M1 沿用 C 类客户端错误码：`C400003`（Host 不在白名单→400）、`C403001`（来源不被允许，涵盖 Host/Oorigin/CSRF→403）、`C429001`（限流→429）。已在 `routes/security.py` 模块 docstring 与 `common/errors.py` 注册表显式记录此冲突与裁决。**确认**采用 C 类码，保留 M2 的 A02xx 码空间不变。
- **(2) switch 审计落地方式（开发提报）**：M0 `set_active` 仅为进程内存句柄、不写库，而 AC7 要求"切换须留痕"。M1 经 `db.write` 唯一入口，以 `set_config(pid, {"last_active_at": <ts>})` 合并写入并同事务追加审计；`ConfigVO` 忽略该键、不改变既有配置语义。**确认**此实现满足 AC7 且不改动 `projects.py` 切换逻辑。
- **(3) safe_path 加固（开发提报 + 主理人审查采纳）**：M0 `safe_path` 仅校验相对 rel 不越界；M1 在路由层对所有 `pid` 入参先 `db.safe_path(pid)` 解析，并加固 base/target 双校验（解析后须落于 `HPSL_HOME/projects/` 内，越界 `C400002`），可防 `pid="../../etc"` 类目录穿越。**确认**采纳，AC5 已覆盖 pid 穿越用例。
