## 1. M2 目标与定位

M2 = 锁定基线 **F4（流程状态机）/ F10（最小延迟复测队列，X2 裁决列入 v0）** 的后端引擎落地。把"八步单元状态机 + PRODUCE 闸门 + 熔断降级记账 + skipped_produce 放行"与"固定间隔（2/7/21 天）延迟复测的最小队列（入队 + 读时到期 + 写回隔离）"实现为**无界面的引擎层**（`engine/state.py` + `engine/review_queue.py`），全部经 M0 的 `db.write` 同事务审计。

**与 M0/M1 的衔接（已核实，必须沿用）**：
- M0 已创建全部 16 库对象，**M2 所需字段已存在，零 DDL 变更**：
  - `unit`：`status`(默认 INIT)、`production`、`produced_at`、`skipped_produce`(默认0)、`close_reason`、`forced_close`、`difficulty_band`、`degraded_from`、`degrade_count`(默认0)、`chosen_from`、`closed_at`。
  - `review`：`id/concept_id/attempt_id/kind(默认'到期')/due/result` + `uk_review_active`(concept_id WHERE result IS NULL)。
  - `attempt`：`kind`(含 `复测`)、`concept_id`、`confirmed_score` 等。
  - `concept`：`verify_status`(默认'未验证')、`last_verified_at`。
- `common/enums.py` 已有 `UnitState`(INIT/PICK/LEARN/PRODUCE/VERIFY/JUDGE/INTEGRATE/CLOSED)、`AttemptKind`(含 `复测`)。
- `common/errors.py` 已注册 M2 专属错误码（基线 §3.5.1 分配给 M2，M1 已确认不占用）：
  - `A020001`（非法状态转移）、`A020002`（未产出进入验证被拒绝）、`A020003`（跳过产出缺少理由）。HTTP 语义均为业务失败（200 + `fail(code)`）。
- M1 已用 C 类码承接 Web 安全（C400003/C403001/C429001），M2 状态机错误语义独立、不冲突。

## 2. 范围边界

### 2.1 In-Scope（M2 必须交付）

1. **单元状态机引擎 `engine/state.py`**：
   - `UnitState` 复用 `common/enums.py`；`TRANSITIONS` 表（§4.1）逐字对齐基线 §3.2.M2.5 迁移表。
   - `move(pid, uid, cur, nxt, *, reason=None, actor="user", expected_version=None)` 实现：① 转移合法性校验（不在 `TRANSITIONS[cur]` → `A020001`）；② **PRODUCE 闸门**（进入 VERIFY 须 `unit.production` 非空，否则须 `reason`（置 `skipped_produce=1` 放行）否则 `A020003`）；③ 状态落账经 `db.write`（同事务审计）；④ 副作用 `LEARN→PICK` 记 `degraded_from=difficulty_band` + `degrade_count+=1`；⑤ 乐观锁（`expected_version`，不一致 → 并发冲突，重读后重试，由调用方处理）。
   - 返回 `UnitStateVO`（含 `allowed_next` 列表，供后续 Web 渲染）。
   - 所有写经 `db.write`；业务代码不直写 `audit_log`。
2. **最小延迟复测队列 `engine/review_queue.py`**：
   - `REVIEW_INTERVALS = (2, 7, 21)`（天）。
   - `enqueue_reviews(pid, concept_ids, closed_at)`：为每个概念插入 `review`(`kind='到期'`, `due=closed_at+2d`)，**幂等**（已有未完成活跃行则跳过，依赖 `uk_review_active`）。
   - `due_reviews(pid, now=None)`：读时计算，返回 `result IS NULL AND due <= now` 按 `due` 升序的条目（首页消费）。
   - `submit_review(pid, concept_id, score, seconds=None, actor="user")`：**写回纪律**——仅写 `attempt(kind='复测',concept_id,confirmed_score=score,seconds)` + `concept.verify_status`(≥ `pass_threshold`→'已验证' 否则 '待验证') + `concept.last_verified_at` + `review.result` 与 `due` 推进到下一档（2→7→21→21 循环）。**绝不写 `unit`/`gap`/任何当前单元账本**；返回 `ReviewResultVO` 含 `wrote_to_current_unit=False`（设计不变量，供断言）。
3. **复用 M0 既有能力**：`db.write`（审计）、`db.query`、时间 `ISO-8601 UTC`、JSON 列 `chosen_from`/`rubric`/`links`。
4. **测试**：
   - `tests/test_state.py`（AC-M2-1/2/3/7 + 审计）：非法转移拒绝、PRODUCE 闸门、skipped_produce 放行、降级记账、审计留痕。
   - `tests/test_review_queue.py`（AC-M2-4/5 + 幂等 + 隔离）：独立触发、写回准确、当前单元零写入、入队幂等。
   - 回归：M0/M1 既有 45 测试仍全绿（AC-M2-8）。

### 2.2 Out-of-Scope（M2 不做，留待后续）

- **Phase 2 视觉 / Phase 3 交互**：M2 为无界面引擎模块，不涉及 UI/交互设计，按 SOP 范围冻结原则跳过（不 spawn 施斓青/刘畅行）。
- **HTTP 路由暴露**（`POST /api/v1/units/{uid}/transition`、`/degrade`、复测端点）：归属 **M10 Web 接入**。M2 仅交付引擎层 + 内部 Python API + headless 测试；Web 层在 M10 复用本引擎。

## 4. 接口契约（引擎内部 API，权威见基线 §3.2.M2 / §3.2.M6）

### 4.1 状态机迁移表（逐字对齐基线 §3.2.M2.5）

| 起始 | 终止 | 触发条件 / 校验 | 副作用 |
|---|---|---|---|
| INIT | PICK | 初版认识非空 | 写 unit.status=PICK |
| PICK | LEARN | 选定候选 | 写 unit.chosen_from |
| LEARN | PRODUCE | 用户主动进入产出 | — |
| LEARN | VERIFY | 跳过产出直入验证（对齐锁定基线 §3.2.M2.5 Step2「cur=LEARN 且 nxt=VERIFY」） | 经 PRODUCE 闸门：production 非空→放行并写 produced_at；为空须 reason→`skipped_produce=1`，无 reason→`A020003` |
| LEARN | PICK | 熔断降级重选（用户确认） | `degraded_from=difficulty_band` + `degrade_count+=1` |
| PRODUCE | VERIFY | `unit.production` 非空 | 写 `produced_at` |
| PRODUCE | LEARN | 用户主动回退 | — |
| VERIFY | JUDGE | 重述+边界题作答完毕 | 写 attempt |
| VERIFY | LEARN | 用户主动回退 | — |
| JUDGE | INTEGRATE | 合法转移（达标/强行闭环判定属 M4/M5） | — |
| JUDGE | LEARN | 未达标回补 | — |
| INTEGRATE | PICK | 整合写入完成（下一单元） | 写 card/concept_edge/review（由调用方组合） |
| INTEGRATE | CLOSED | 单元终止（terminal） | 调用方显式写入 `closed_at`（`move()` 不自动；M4/M5 闭包时写） |

> **PRODUCE 闸门（M2 核心）**：凡**进入 VERIFY** 的转移（`PRODUCE→VERIFY` 与 `LEARN→VERIFY` 两路均经此闸门），须 `unit.production` 非空；为空则要求 `reason` 非空 → 置 `skipped_produce=1` 后放行；无 `reason` → `A020003`。未满足且无 reason 时 `unit.status` 不变、无审计记录（对齐 AC-3.2/AC-3.3）。
> **非法转移**：`nxt ∉ TRANSITIONS[cur]` → `A020001`，`unit.status` 与审计均无该转移（对齐 AC-3.9）。
> **错误码裁决（主理人）**：进入 VERIFY 而无 `unit.production` 且无 `reason` 的拒绝，采用 **`A020003`（跳过产出缺少理由）**——对齐锁定基线 §3.2.M2.5 Step2 逐字约束与错误码注册表含义。基线序列图（§3.2.M2.x）的同事件标注 `A020002` 系锁定基线内部不一致；M2 以详细接口契约的 `A020003` 为准，AC-M2-2 落码为 `A020003`（AC 表 §5 的 `A020002` 标注为宽泛表述，本规格已更正）。
> **`closed_at` 裁决（主理人）**：`INTEGRATE→CLOSED` 的 `move()` **不**自动写 `closed_at`，保持 `move()` 纯状态转移语义；`closed_at` 由 M4/M5 闭环逻辑（JUDGE→INTEGRATE 达标/强行闭环）在闭包时显式写入，或由调用方/测试传入。

### 4.2 复测队列最小接口（对齐基线 §3.2.M6.4/5，X2 裁决列入 v0）

- `enqueue_reviews(pid, concept_ids: list[str], closed_at: str)`：每概念插 `review`（`kind='到期'`, `due = closed_at + 2天`），幂等跳过已有活跃行；`actor=system`。
- `due_reviews(pid, now: str | None = None) -> list[ReviewItemVO]`：返回 `result IS NULL AND due <= now` 按 `due` 升序。
- `submit_review(pid, concept_id, score: float, seconds=None, actor="user") -> ReviewResultVO`：
  - 写 `attempt`（`kind='复测'`, `concept_id`, `confirmed_score=score`, `seconds`）；
  - 写回 `concept.verify_status`（`score >= pass_threshold`→'已验证' 否则 '待验证'）、`concept.last_verified_at = now`；
  - **保持 `review` 行活跃**（`result` 维持 `NULL`，与 `uk_review_active` 唯一活跃行约束一致，以支持 2→7→21 循环重新到期），仅把 `due` 推进下一档（2→7→21→21 循环）；复测结果以 `attempt` 记录为准（`attempt_id` 可顺带回写 `review`）；
  - **纪律不变量**：绝不写 `unit`/`gap`/任何当前单元账本；`wrote_to_current_unit` 恒 `False`（供断言）。
- `REVIEW_INTERVALS = (2, 7, 21)`；`pass_threshold` 取 `config.pass_threshold()`（默认 0.7）。

## 6. 实现注意

- **不引入 ORM**：SQL 全部手写，复用 M0 `db.write` 唯一写入入口；审计自动附随。
- **不改动基线文档**：实现只在新建 `engine/` 与 `tests/`，不碰 `.workbuddy/delivery/`。
- **headless**：`engine` 不依赖 `routes`/`app`，便于 M10 接入与 headless 测试。
- **错误码**：M2 专用 `A020001/2/3` 已在 `errors.py` 注册，直接 `raise BizError("A020001")`；不得新增 A02xx 之外的冲突码。
- **时间**：`produced_at`/`due`/`last_verified_at` 一律 `ISO-8601 UTC`（复用 `db._now_utc()` 或等价）。
- **幂等入队**：依赖 `uk_review_active`（`concept_id` WHERE `result IS NULL`），已存在活跃行则跳过，不重复入队。
- **隔离断言**：`submit_review` 内部可加显式断言/校验，确保不触达 `unit`/`gap` 表（由 `db.write` 白名单 + 测试 `wrote_to_current_unit` 双重守护）。
- **复测循环（关键纪律）**：`submit_review` **不得**把 `review.result` 置为非空——否则 `due_reviews` 的 `result IS NULL` 过滤会使其永久失活，2→7→21 循环断裂。正确做法：保持活跃行（`result` 维持 `NULL`）+ 推进 `due`，循环由 `due_reviews` 反复到期触发；复测结果以 `attempt` 为准。
