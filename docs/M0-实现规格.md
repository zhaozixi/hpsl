## 2. 范围边界

### 2.1 In-Scope（M0 必须交付）

1. **工程骨架**：`hpsl` Python 包（后端），含 `app.py / config.py / db.py / projects.py / common/ / models/`，依赖方向 `roles|engine|web → common,models`，禁止反向。
2. **路径与配置**：`config.py` 解析 `HPSL_HOME`、服务端口、默认阈值（ConfigVO）。
3. **连接管理（db.py）**：每项目一个 `project.db`，WAL 模式，**单一写连接 + busy_timeout=5000ms** + 多读连接；连接工厂。
4. **迁移（db.py）**：`PRAGMA user_version` 幂等迁移，**建库时一次性创建全部 16 个库对象**（15 表 + chunk_fts FTS5 虚表）；不建额外版本表。
5. **审计写入（db.py）**：`write(table, row, actor)` 唯一写入口——白名单校验 → `BEGIN IMMEDIATE` → UPDATE/INSERT（**禁用 REPLACE**）→ 同事务追加 `audit_log` → COMMIT；SQLITE_BUSY 排队重试（禁止静默覆盖）。
6. **项目管理（projects.py）**：创建项目（建目录 0700 → 迁移 → 写 project 行）、列出、切换、active 句柄、配置读合并/写覆盖。
7. **M1 内部 API**：`create_project / list_projects / active_project / get_effective_config / set_config`。
8. **单元自测**：db.py / projects.py 关键路径的 pytest 用例（见 §10 测试守护）。

### 2.2 Out-of-Scope（M0 不做，留待 M1–M5）

- FastAPI 路由层（`/api/v1/projects` 等 HTTP 端点）、HTMX 页面、Web 安全校验（Host/Origin/CSRF）——M10 落地；`app.py` 现为完整 FastAPI 入口（M0 仅预留空壳与 `serve` 入口，M10 起填充）。

## 5. 连接纪律（C-01，§4.1 / §5.2）

| 项 | 取值 | 实现要点 |
|---|------|---------|
| 数据库类型 | SQLite 3.45+（Python 标准库 `sqlite3`） | 启动前断言 `sqlite3.sqlite_version >= '3.45.0'` 且 FTS5 可用 |
| 写连接 | **单一写连接**（`BEGIN IMMEDIATE` + busy_timeout 5000ms） | 全局唯一写连接对象，所有 `write()` 经此；天然串行 |
| 读连接 | 多读连接（WAL 读不阻塞写） | 读路径可开多连接；只读不写 |
| 冲突处置 | 排队串行；SQLITE_BUSY 耗尽 → 排队重试 | **禁止静默重试覆盖**（D-03）；返回 B999002 |
| 外键 | 每连接 `PRAGMA foreign_keys=ON` | REPLACE 会触发外键删除语义，故 `write()` 禁用 REPLACE |
| 时间字段 | TEXT，ISO-8601 UTC（如 `2026-10-15T08:30:00.123Z`） | 禁止存本地时间；字典序=时间序 |
| JSON 字段 | TEXT 存 JSON，`json.dumps(ensure_ascii=False)` | config/chosen_from/rubric/links/providers/change/prev |
| 软删除 | 不使用；废弃用状态值或审计撤销 | 避免污染唯一索引与统计口径 |

连接管理建议：db.py 维护一个进程级写连接单例 + 读连接工厂；`PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000`、`PRAGMA foreign_keys=ON` 在连接建立时设置。

## 6. 迁移策略

- 版本记录：`PRAGMA user_version`（整数）。
- 幂等：`CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS` + `CREATE VIRTUAL TABLE IF NOT EXISTS`（FTS5 不支持 IF NOT EXISTS，需用 `SELECT name FROM sqlite_master` 判断后创建）。
- **建库即全建**：v0 为 0→1 新建系统，"MVP 数据模型按完整版一次做对"——15 表 + chunk_fts 在建库时全部创建（共 16 个库对象）。`user_version` 初始置为 1。
- 后续演进纪律：仅允许前向兼容（新增表/列带默认值）；不可回滚变更（DROP COLUMN 等）禁止与代码同发布（属 v1+，M0 不涉及）。
- 迁移失败 → 事务回滚 + 告警 AL-02（M0 实现：抛出明确异常并清理半成品目录）。

## 8. db.py 设计（M7 四本账与审计核心）

### 8.1 TABLES 写白名单
`TABLES` 常量（dict：表名 → 允许列集合）**逐字对齐 §7 的 14 张业务表 + audit_log（共 15 张表）**（`audit_log` 不在写白名单，仅由 `write()` 内部追加）。代码生成/校验：表名与列名只允许来自此常量，外部输入一律不可作为表名/列名（防注入 T-06）。

### 8.2 `write(conn_or_project, table, row, actor)` —— 全部账本写入唯一入口
流程（§3.2.M7.4 / §3.2.M7.5）：
```
Step 1 白名单校验：
  ├── table ∈ TABLES？否 → KeyError（表名来自代码常量，不接受外部输入）
  ├── row 键 ⊆ TABLES[table]？否 → ValueError（未知列）
  └── 拼接到 SQL 的只有白名单内的表名/列名；值一律参数绑定
Step 2 同事务写入（单一写连接）：
  ├── BEGIN IMMEDIATE（busy_timeout=5000ms 排队等待）
  ├── SELECT prev（旧值）→ prev 存在则 UPDATE，否则 INSERT
  │     └── 禁止 REPLACE：REPLACE 实为 DELETE+INSERT，触发外键删除语义且不进审计
  ├── INSERT audit_log（ts / actor / table_name / row_id / change / prev）
  └── COMMIT（业务写入与审计要么都成功要么都回滚）
Step 3 冲突处置：
  └── SQLITE_BUSY（busy_timeout 耗尽）→ B999002：排队串行重试，禁止静默重试覆盖（D-03）
```
- `actor` ∈ {user, clerk, system}。
- `change` = 完整新行 JSON；`prev` = 旧行 JSON（INSERT 为 NULL）。
- 撤销 `undo(audit_id, actor)`：读 audit_log → 校验 expected_prev_hash 与当前行一致 → 按 prev 回滚目标行（prev=None 则删除）→ 本次撤销动作本身也写 audit_log（actor=user）。旧值指纹不匹配 → A070002。
- 异常 → ROLLBACK（业务表与审计同时回滚）。

### 8.3 连接工厂
- `get_write_conn(pid)`：返回（并缓存）该项目的单一写连接，已设 WAL / busy_timeout=5000 / foreign_keys=ON。
- `get_read_conn(pid)`：新建只读连接（WAL 读）。
- 项目路径经 safe_path 约束（M0 至少保证不越出 `HPSL_HOME/projects/{pid}/`）。

## 9. projects.py 设计（M1 项目管理与配置）

### 9.1 内部 API 契约（§3.2.M1.2）
| 内部 API | 用途 | 调用方 |
|---|------|-------|
| `create_project(name, goal) -> Project` | 建目录（0700）→ 迁移建表 → 写 project 行（actor=user） | M10 向导 |
| `list_projects() -> list[Project]` | 扫描项目根目录 | M10 首页 |

### 9.2 `create_project` 流程（§3.2.M1.5）
```
Step 1 参数校验：name 非空、≤100 字符、全局唯一（重名 → A010002）；goal 非空、≤500 字符
Step 2 建目录：HPSL_HOME/projects/{uuid}/，权限 0700；异常（磁盘不足/权限拒绝）→ B999001 + 清理半成品目录
Step 3 迁移建表：执行 §7 全部 DDL，置 user_version=1；失败 → 回滚 + 告警 AL-02
Step 4 写 project 行：actor=user，经 db.write 同事务追加 audit_log
Step 5 生效：切换 active_project()，后续全部模块经此句柄访问（跨项目零共享）
```

### 9.3 关键结构（§3.2.M1.3，节选）
- `ProjectCreateRequest`：name(str,1~100,全局唯一) / goal(str,1~500) / initial_belief(str|None,≤2000,默认空)。
- `ProjectVO`：id(UUIDv4 hex) / name / goal / initial_belief / db_path(展示用,不暴露目录遍历) / created_at(ISO-8601 UTC)。

## 11. 测试守护基线（实现期发布门禁，§7.4）

M0 必须实现并 100% 通过的断言（其余 test_security/test_grading/test_cost/test_contracts 待 M10/M5/M8 再补）：

- **test_projects**：两项目库互不可见；项目 B 的资源 ID 在项目 A 上下文使用被拒绝（物理隔离 + active 句柄 + 资源归属校验）。

- **test_audit**：每笔 `write` 必有 audit_log 条目；撤销动作本身留痕；旧值指纹不匹配的撤销被拒（A070002）。

## 12. 实现注意事项（来自基线交叉约束）

- **不建 ORM**：所有 SQL 手写；`db.write` 是账本写入唯一入口，业务模块不得绕过。
- **JSON 字段**：写入 `json.dumps(ensure_ascii=False)`，读取按需 `json.loads`；SQLite JSON1 扩展可用于查询。
- **主键约定**：绝大多数表 `TEXT` UUIDv4 hex；`turn` 与 `audit_log` 用 `INTEGER PRIMARY KEY`（rowid 顺序=写入顺序，审计回放依赖）。
- **金额**：`cost REAL`（美元），tokens 为事实源，cost 为派生展示值。
- **错误码**：6 位错误码（如 A010002 项目名已存在 / B999001 磁盘或权限 / B999002 busy_timeout 耗尽），经 `common/errors.py` + `common/result.py` 封装。
- **traceId**：审计/日志全链路 contextvar（M0 预留，可先置固定值）。
