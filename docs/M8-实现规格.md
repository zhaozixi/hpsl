## 1. M8 目标与定位

M8 = 锁定基线 **§3.2.M8 成本估算与预算模块（BC-7 支撑域，D-05 落地）** 的后端编排层。

**范围边界（关键澄清）**：
- M0 的 `db.py` 已落地 `llm_call` 表（16 库对象之一）与 `write`（白名单 + 同事务审计）/`undo` 基座。M8 **不重造写入基座**，而是在其上增量实现成本估算与预算编排。
- M8 NEW = `record_call`（每次 Provider 调用出口记一行 llm_call）、`session_cost`（按会话聚合 + 当月累计 + 三态）、`budget_status`（ok/warn/blocked 读时判定）、`confirm_continue`（超限确认放行并写审计留痕）；以及 §3.2.M8.3 的 `CostEstimateVO` / `CostConfirmRequest` DTO。
- 业务逻辑内部流动，用户经 **M10**（会话内实时估算展示 + 超限确认弹层）间接触达；涉及 **M4 模型适配**（Reply 计量出口）、**C-01 SQLite**（llm_call 表）、`models/pricing.yaml`（价格表，用户可维护）的交互。

**承接已核实资产（必须沿用）**：
- `db.write`（M0）：白名单 + 同事务审计，所有账本写入唯一入口；`db.undo`（M0）：A070001/A070002 指纹回滚。
- `errors.py` 已注册 `A080001`（预算超限待确认）；M8 新增 `A080002`（成本模块未激活项目）。
- `models/registry.py`（防腐层）：`pricing(model_id)`（读 pricing.yaml）、`get_model(model_id).provider`（由模型推导 provider）。
- 纪律红线（全程沿用）：密钥红线（D1 §6.5）、隔离红线（O13）、错误码分段（M8 = A08xx）、**零 DDL**（M0 锁定的 16 库对象中 llm_call/audit_log 已含 M8 所需列）、headless 不依赖 routes/app、`write` 唯一写入口（受限扩展见 D-M8-1）。

## 2. 范围边界

### 2.1 In-Scope（M8 必须交付）

1. **调用记账 `record_call(role, reply, session_id, unit_id) -> CostEstimateVO`（§3.2.M8.2 内部 API）`engine/cost.py`**
   - 每次 Provider 调用出口记一行 `llm_call`（role/provider/model/session_id/unit_id/input_hash/tokens_in/tokens_out/cost/ts），actor=`system`，经 `db.write` 同事务审计。
   - provider 由 `reply.model` 经 `registry.get_model(model).provider` 推导（reply.raw 不含 provider，已核实）；tokens_in/out 由 `reply.raw['usage']` 兼容归一化（OpenAI `prompt_tokens/completion_tokens` 与 Anthropic `input_tokens/output_tokens`）；cost 按 pricing.yaml 计算（未登记模型记 0.0）。
   - 返回记账后的 `CostEstimateVO`（便于 M4 即时刷新）。
2. **会话花费估算 `session_cost(session_id) -> CostEstimateVO`（§3.2.M8.2）**
   - 会话级聚合（SUM tokens × pricing → cost_usd）、当月累计（跨会话，自然月聚合 UTC）、预算上限（项目配置 `budget_cap_usd`）、三态 status、confirmations、computed_at。
3. **预算三态 `budget_status(session_id) -> str`（§3.2.M8.2）**
   - 读时计算 ok / warn / blocked（无持久状态）；M4 闸门消费，blocked 时由 M4 升 A080001（M4 范围，M8 仅提供 status 判定）。
4. **超限确认 `confirm_continue(session_id, actor='user') -> CostEstimateVO`（§3.2.M8.2）**
   - 写审计留痕（经 `db.append_audit_event`，table_name=`cost_confirm`）+ 本会话放行（blocked→warn，confirmations 由 audit_log 派生）；返回更新后的 `CostEstimateVO`。
5. **DTO/VO（`common/dto.py`）**：`CostEstimateVO` / `CostConfirmRequest`（§3.2.M8.3）。
6. **错误码（`common/errors.py`）**：新增 `A080002`（成本模块未激活项目）。
7. **审计事件写入（`db.py`）**：新增 `append_audit_event`（受控直写 audit_log，零 DDL，§3.2.M8.4 序列图显式要求）。
8. **导出补齐（`engine/__init__.py`）**：`record_call` / `session_cost` / `budget_status` / `confirm_continue`。
9. **测试**：`tests/test_cost.py`（17 例，覆盖记账/三态/确认放行/跨会话累计/跨月隔离/边界值/未激活/非法 actor/缺 raw/FK/clerk actor）。
10. **回归**：M0–M7 既有 **156** 测试仍全绿（零 DDL、零破坏）。

### 2.2 Out-of-Scope（M8 不做，留待后续）

- **HTTP 路由暴露**（/api/v1/sessions/{sid}/cost、/api/v1/cost/monthly、/api/v1/sessions/{sid}/cost/confirm、/api/v1/settings/budget）属 M10 Web 接入；M8 仅落地引擎原语与 DTO。`CostConfirmRequest` 为 M10 REST 层消费入参（acknowledged 恒 true 防误触）。
- **M4 闸门升 A080001 的调用编排**：M8 提供 `budget_status` 判定，但「blocked → 抛 A080001 → 弹层 → confirm_continue」的接线属 M4/M10 范围。
- **当月累计按角色/模型拆分的 `CostBreakdownVO`**：REST GET /api/v1/cost/monthly 的响应 VO 属 M10；M8 内部 API 仅提供 `session_cost` 所需的跨会话当月累计聚合。
- **计费重试记账接线**：M4 适配器 `_on_call` 钩子接 `record_call` 属 M4 范围；M8 仅保证 `record_call` 可重复调用（每调用独立记一行，符合基线「重试视为新调用逐次记账」）。

| D-M8-6 | `record_call` 前置：session_id（及 unit_id 若非 None）对应业务行须已存在（FK 约束） | llm_call.session_id/unit_id 为 REFERENCES；M4 调用出口前必已建 session/unit | M8 不自动建 session/unit；测试经 `_seed` 预建 | 单一写入口纪律；FK 由调用方保障 |

## 4. 计价公式换算（pricing.yaml ↔ 基线公式）

基线 §3.2.M8.5 公式：`cost = tokens_in / 1e6 × price_in + tokens_out / 1e6 × price_out`，其中 price 为「每 1e6 tokens」单价。

`pricing.yaml` 给的是「每 1K tokens」（`in_per_1k` / `out_per_1k`）。换算：`price_in_per_1e6 = in_per_1k × 1000`，代入得：

```
cost = (tokens_in × in_per_1k + tokens_out × out_per_1k) / 1000.0
```

校验（gpt-4o-mini，in_per_1k=0.00015 / out_per_1k=0.0006，1M/1M tokens）：
`(1e6×0.00015 + 1e6×0.0006) / 1000 = (150 + 600) / 1000 = 0.75 USD` ✅

cost 在 `record_call` 时按定价计算并落 `llm_call.cost`（REAL），`session_cost` 对 `cost` 列 SUM，避免浮点累计误差（基线 §3.2.M8.5 「cost 为派生展示值」）。

## 7. 实现要点与复用清单

- **复用 M0 资产（零新增业务写入逻辑）**：`db.write`（白名单 + 同事务审计）、`db.undo`、`db.TABLES` 白名单、`db._now_utc`。
