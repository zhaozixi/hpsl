## 2. 关键决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D-M27-1 | 运维端点集中在 `routes/ops.py`，不散到各模块 | 都是"读账本/读成本/撤销"类横切能力；避免与 unit/stats 路由互相 import |
| D-M27-2 | 审计列表只返回 5 个元数据字段 | `change/prev` 可能含正文；避免列表页意外泄露，也控制响应体积 |
| D-M27-3 | 撤销走 `db.undo` 原语，不重写回滚逻辑 | 指纹校验、事务、留痕都在 M0 已验证；路由只做参数与响应 |
| D-M27-4 | 撤销 HTMX 响应 `HX-Refresh` | 撤销会影响多张表与审计列表，整页刷新最可靠 |
| D-M27-5 | 输入预览复用角色上下文构建器与 `assembler.preview` | 保证"预览看到的 == 实际会发的"（同一 allow 白名单） |
| D-M27-6 | graph 用 DOM API 而非转义函数拼 HTML | 从根上消除注入面，避免"漏转义某个字段" |
| D-M27-7 | HTMX 用官方原样文件（未自定义构建） | 可校验（`node --check` + 跨 CDN 哈希）；升级路径明确 |
