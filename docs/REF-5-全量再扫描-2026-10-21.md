## 3. 本轮发现与处置建议

### F-01【P2，已修复】打包自检不可重入：第二次运行必然失败

- 现象：连续跑两次 `python scripts/check_package.py`，第二次报
  `error: [WinError 183] 当文件已存在时，无法创建该文件。: 'build\bdist.win-amd64\wheel\hpsl-0.1.0.dist-info'`，
  以 `ERROR: Failed to build one or more wheels` 收场，脚本输出「构建失败」。
- 根因：`check_package.py` 走 `pip wheel` 默认路径，构建落在仓库内 `build/`；
  Windows 上第二次构建无法在已存在的 `bdist.win-amd64/wheel` 下重建 `dist-info` 目录。
- 复现性：**稳定复现**（`rm -rf build` → PASS 108 条目；紧接着再跑 → 必失败）。
- 影响：打包自检的结论依赖「上一次是否留下 `build/`」。REF-4 记录的 `PASS (108 条目)` 只在干净环境成立，
  本地连跑或 CI 复用工作区时会误报发布门禁失败。
- 建议（二选一，均只改脚本，不动业务代码）：
  1. 构建前 `shutil.rmtree(repo/"build", ignore_errors=True)`；
  2. 改用临时目录承载构建（`--wheel-dir` + 临时 `build` 根），彻底不污染工作区。
  建议顺手把 `build/` 加入脚本的退出清理，确保「失败也不留残留」。
- **已落地（M41 追加收口）**：新增 `_purge_build_dir()`——构建**前**清一次（吃掉历史残留）、
  构建**后**再清一次；清理失败重试三轮，仍失败则 `stderr` 明确告警（不再 `ignore_errors` 静默）。
  同时把两处 `subprocess.run` 补 `encoding="utf-8"`（避免 GBK 解码把真实错误吞成空输出）。
  **验收**：手动植入 `build/bdist.win-amd64/wheel/hpsl-0.1.0.dist-info` 残留后连跑两次，
  均为 `PASS`（108 条目），结束后 `build/` 零残留。
