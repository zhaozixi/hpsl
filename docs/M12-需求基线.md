# HPSL v0 · M12 需求基线（UI 设计升级 · 独立里程碑）

> 文档类型：需求基线（M12 UI 设计升级）
> 日期：2026-10-17
> 承接：M11（首次启动向导 / 密钥持久化 / Markdown 导出，已封版，298 passed）
> 实现位置：`D:/workspace/TLF/hpsl/`
> 交付形式：docs 报告 + 任务清单（HPSL 非 git 仓库）

---

## 一、目标

将 Web 界面从「能用但朴素」的开发者工具观感，升级为「好看且好用」的**统一设计系统**。建立可复用的视觉 token 与组件类，消除逐页随手写样式，提升可读性、信息层次与跨设备一致性。

当前状态（实测）：`app.css` 53 行、18 个模板全部继承 `base.html`、全树仅 3 处内联 `style=`；已具备深色顶栏 + 居中主栏 + 卡片/提示条/向导步骤/CTA 的基础语言，但**无 token、无响应式、无统一组件库、无微交互**。

---

## 二、范围边界（硬）

- **仅改** `hpsl/templates/**` + `hpsl/static/app.css`（必要时 `app.js`）。
- **不碰** `routes/`、`engine/`、`db.py`、`models/`、`config.py`、`app.py`（含中间件顺序）、错误码、16 库对象。
- 零 DDL；引擎 headless 不变；安全分层（读/写）不变；密钥红线不变。
- 仅做视图层改造，**不改任何 HTTP 端点语义与返回结构**（htmx 片段的 id/hook 须保留，避免破坏前端交互）。

---

## 三、设计方向决策（主理人定）

1. **保留品牌观感，升级为 token 体系**：沿用现有深色导航 `#1f2937` + 浅灰底 `#fafafa` 作为基调，避免大改导致主理人不适；但全部色值收敛进 `:root` 变量。
2. **设计 token（`:root` CSS 变量）**：颜色（品牌/表面/边框/文本/语义四色）、间距（4/8/12/16/24px 栅格）、圆角（6/8/10px）、字号、阴影（扁平→轻投影）。
3. **统一组件类**：`.btn` / `.btn-primary` / `.input` / `.select` / `.table` / `.card` / `.grid` / `.badge` / `.banner` / `.modal` / `.nav`。废弃散落硬编码样式。
4. **8px 栅格留白节奏**：统一区块/卡片/行间距。
5. **响应式**：`≤720px` 顶栏折叠为纵向/汉堡、主栏边距自适应、表格横向滚动而非溢出。
6. **轻量图标**：内联 SVG / Unicode，**不引外部图标库**（离线优先，与 HTMX CDN 策略一致）。
7. **微交互**：按钮/链接/卡片的 `hover` / `active` / `:focus-visible` 反馈（聚焦环、轻微位移/阴影）。
8. **暗色模式**：本期**不做**（范围收敛）；token 结构预留以便将来扩展。

---

## 四、验收

- 全量 `pytest` **零回归**（目标维持 298 passed / 0 skipped）。
- 零 DDL；16 库对象不变。
- 18 个模板在桌面（≥1024px）与移动（≤720px）宽度下均可读、**无横向溢出、无破损布局**。
- 设计 token 集中在 `:root`；除必要遗留外无散落硬编码色值。
- htmx 片段（`_unit_wf_panel` / `_unit_cc_row` / `_quota_modal`）的 id/hook 与交互不受影响。
- 仅 2 个 pilot 页（index / wizard）在批次1 全量套用；其余页批次2 套用同系统。

---

## 五、批次划分

- **批次1（基础 + pilot）**：`app.css` 改写为 token 设计系统 + `base.html` 外壳升级（响应式顶栏/容器/通知区）+ `index.html` / `wizard.html` 套用新系统 + 验证（pytest 零回归、布局自查）。
- **批次2（全量铺开）**：其余 16 模板套用同一设计系统（含 htmx 片段组件化、表格/表单/模态统一），并做移动端布局走查。

---

## 六、纪律硬约束

- 零 DDL；`db.write` 唯一入口（本里程碑不涉及写）。
- 引擎 headless 不变；`app.py` 中间件顺序（Security 在内、TraceId 在外）不变。
- 错误码不新增、不改动；安全分层不变；密钥不进视图、不随导出。
- 视图层仅消费既有数据，不改变路由/端点契约。

---

## 七、开放问题（主理人可覆写）

- 品牌色是否保留深 slate（默认：保留，仅 token 化）。
- 是否要暗色模式（默认：本期不做，留 token 结构）。
- 如主理人对 pilot 页效果不满意，批次2 前可整体调整方向（故先 pilot 再铺开）。

---

## 八、风险

- UI 主观性强：先 pilot 两页给主理人看效果，确认方向后再铺开全部模板，降低返工。
- 模板较多（18 个）：批次2 需逐页核对 htmx hook 与既有测试断言文本不被破坏。
