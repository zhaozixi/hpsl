## 1. 实现要点

- **`hpsl/models/models.yaml`**：provider 增 `kind`/`base_url` 字段；OpenAI 厂商 id 由 `openai_compat` 重命名为
  `openai`（display「OpenAI（GPT 系列）」、`kind=openai_compat`、`base_url=https://api.openai.com/v1`）；新增
  `gemini`（`kind=gemini`）、`deepseek`/`qwen`/`zhipu`/`moonshot`/`doubao`（均 `kind=openai_compat`，各自 `base_url`）。
  模型条目：保留 `gpt-4o-mini`/`claude-3-5-haiku-20241022`；`deepseek-chat` 改 `provider: deepseek` 但**保留
  `family: deepseek, derived_from: gpt4o`**；新增 `gpt-4o`/`gemini-1.5-flash`/`deepseek-reasoner`/`qwen-*`/`glm-4-*`/
  `moonshot-v1-*`/`doubao-pro-32k` 等。
- **`hpsl/models/registry.py`**：`_ensure` 由「仅存 display」改为「存完整 provider meta（display/kind/base_url）」；
  新增 `provider_kind(provider)`；`default_base_url` 优先读 YAML `base_url`（兜底 `https://api.{provider}.example/v1`）；
  `list_providers` 以 YAML 为准；`build_adapter` 先取 `kind = provider_kind(...)` 再分流（anthropic / gemini / 默认
  openai_compat）；`_DEFAULT_BASE_URLS` 清空为 `{}`（YAML 单一事实来源）。模块级新增 `provider_kind()` 函数。
- **`hpsl/models/connectivity.py`**：`test_connection` 由「按字面 `provider == "openai_compat"`」改为「按
  `registry.provider_kind(provider)` 分流」（openai_compat→Bearer `/models`；anthropic→`x-api-key`+`anthropic-version`；
  gemini→`key` 参数）；国内厂商统一走 openai_compat 分支。
- **向导/设置页零改动**：`wizard.py` 与 `settings_keys.py` 本就动态取 `registry.list_providers()`，新增厂商自动出现在
  下拉、密钥存储、连通性测试三处。
