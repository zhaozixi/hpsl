# M38 独立密钥入口 + 费用双币展示

> 两件事一起做，因为它们是同一个痛点：**「我花了多少钱」和「我该去哪儿填密钥」都不该靠猜。**

## 一、独立密钥入口（`/keys`）

### 之前的问题

M37 模拟测试发现：全站唯一能填密钥的地方是向导第 2 步。`settings.html` 从来没有密钥区块（`git log -S` 追溯过），导航里也没有入口，而错误文案还把用户往「设置 → 密钥」引。结果就是——用了一个月想换把密钥，只能重走一遍向导。

### 现在的样子

顶部导航「设置」右侧新增 **密钥**，独立页面 `/keys`：

| 能力 | 实现 |
|---|---|
| 不需要先有项目 | 密钥是全局的，换项目也该能改；路由不依赖 `active_project()` |
| 三家厂商各一行 | DeepSeek / 千问 Qwen / 智谱 GLM（来自 `models.yaml`，不硬编码） |
| 状态一眼可见 | 「已配置 · 尾号 3456 · 存放于本地加密文件」/「未配置」 |
| 保存 | `PUT /api/v1/settings/keys/{provider}`，成功后清空输入框、就地更新徽标（不整页刷新） |
| 测试连接 | `POST /api/v1/providers/{p}/test`，成功/失败都给中文结论 |
| 保险库锁定 | 页面顶部横幅说明原因并禁用保存；不让用户白提交一次再吃 A040003 |

安全红线未动：GET 只返回 `has_key / stored_in / key_tail`，完整密钥不进 HTML、不进日志、不进导出。浏览器实测确认：保存后整页源码里搜不到完整密钥。

同时把 M37 修过的那三处文案从「向导 → 第 2 步」改成「密钥」页——现在它真的存在了。

## 二、费用双币展示

### 口径

**记账仍是美元**：`llm_call.cost_usd`、`pricing.yaml`、`budget_cap_usd`、预算三态判断全部不变。人民币只活在展示层，不参与任何计算与比较。这是有意为之——预算判断一旦掺进汇率，同一笔历史花费的含义会随汇率漂移。

### 汇率从哪来

项目配置新增 `usd_cny_rate`（默认 7.2），设置页可改，实时预览：

- 改完立即影响预算页、统计页、项目详情、角色调用回执；
- 不联网、不引入外部依赖（本地单机形态下，每次渲染去请求牌价既慢又不可靠）；
- 界面始终把汇率写出来（「1 美元 ≈ ¥7.35」），避免被当成实时牌价。

### 展示形态

| 位置 | 之前 | 现在 |
|---|---|---|
| 预算页表格 | `10.5` / `10.0` | `$10.50（约 ¥77.18）` / `$10.00（约 ¥73.50）` |
| 超限弹层 | `累计 $10.5 / 上限 $10.0` | `累计 $10.50（约 ¥77.18） / 上限 $10.00（约 ¥73.50）` |
| 统计页累计花费 | `2.5000` | `$2.50` + 下一行 `≈ ¥18.00`；柱状图 tooltip 与峰值同样双币 |
| 项目详情 | `$10.00` | `$10.00（约 ¥73.50）` |
| 角色调用回执 | `本次 $0.000123 · 累计 $0.0456` | `本次 $0.000123（约 ¥0.0009） · 累计 $0.0456（约 ¥0.34）` |

小数位规则：美元 ≥1 两位、≥0.01 四位、更小六位、零两位；人民币 ≥0.01 两位、更小四位、零两位。小额费用不会因为四舍五入变成 `¥0.00`。

## 五、未做

- **删除密钥**：`secrets` 门面只有 set/get，没有 delete；要支持「清除」得先加底层能力，本轮没碰。当前「覆盖保存」可达到换 key 的目的。
- **汇率自动更新**：按本地单机形态，不联网取牌价；要接实时汇率应作为可选开关单独设计（含失败回退与缓存）。
- **导出里的双币**：`export` 生成的是 md 记账明细，仍只写美元原值（导出用于对账，掺入折算反而增加歧义）。
