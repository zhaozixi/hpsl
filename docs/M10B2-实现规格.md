## 1. 第二批范围

### 1.1 复测页 `/review`
- 新增 `hpsl/templates/review.html`（extends `base.html`）：渲染当前激活项目**到期复测列表**（由 `due_reviews(pid)` 取得 `ReviewItemVO`）。
- 新增页面路由（独立模块 `routes/review.py` 的 `page_router`）：`GET /review` → `read_security`；无激活项目 → 渲染带「尚未选择项目」提示（与 `/ledger` 一致）。context：`project`（active.to_dict）、`items`（list[ReviewItemVO.to_dict]）。
- 列表每项展示：概念名（concept_name）、类型（kind）、间隔档（interval_days 天）、到期（due），以及一个「开始复测」按钮。

### 1.2 REST 端点（消费 M6 引擎）
- `GET /api/v1/reviews/due`（`read_security`）→ `ok([ReviewItemVO.to_dict...])`；无激活项目 → A010001。
- `POST /api/v1/reviews/{review_id}/start`（`write_security`）→ 调 `start_review(pid, review_id, question=...)`，返回 `ReviewStartVO` 字段（手工构造 dict，因 `ReviewStartVO` 引擎未提供 `to_dict`）。htmx 请求时返回评分表单片段（包裹于 `#panel-{review_id}`，供 `outerHTML` 替换）。
- `POST /api/v1/reviews/{review_id}/submit`（`write_security`）→ 解析 `score`（须 ∈[0,1]，否则 C400001）→ 调 `submit_review_by_id(pid, review_id, score, seconds=..., actor="user")`，返回 `ReviewResultVO.to_dict()`。htmx 请求时返回结果片段（通过/未通过 + 下次复测，包裹于 `#panel-{review_id}`）。

### 1.3 HTMX 交互（与领先批次一致）
- 「开始复测」按钮：`hx-post` 到 start 端点，`hx-target="#panel-{id}"` `hx-swap="outerHTML"` → 面板替换为自评表单（含可选 question 透传文本）。
- 自评表单：`hx-post` 到 submit 端点，同目标同 swap → 面板替换为结果片段。
- CSRF 双提交由既有 `static/app.js`（`htmx:configRequest` 注入 `X-CSRF-Token`）保障；写请求由浏览器自动附加 Origin，满足 `write_security`。

### 1.4 导航
- `hpsl/templates/base.html` header 增加「复测」链接（`/review`），与「设置」「项目管理」并列。

### 1.5 挂载
- `hpsl/app.py`：新增 `from .routes import review as review_routes`；`include_router(review_routes.api_router)` 与 `include_router(review_routes.page_router)`（置于既有的 governance / ledger 路由之后）。**中间件顺序不变**（SecurityMiddleware 在内、TraceIdMiddleware 在外）。

## 2. 纪律约束（必须守住）

- **零 DDL**：不得新增表/列/索引；所有写经 `engine.review_queue` → `db.write`（写 attempt/concept/review 既有表）。`routes/review.py` 不得直写 `db.write`、不得含 CREATE/ALTER。
- **写唯一入口**：仅经 engine 内部 `db.write`（既有表）；不得直写 `audit_log`/原生 SQL。
- **错误码**：复用既有（`A010001` 无激活项目、`A060001` 复测条目不存在/已完成、`C400001` 参数非法、`C403001` 来源不被允许、`C429001` 限流）；无新码空间。
- **安全**：页面 GET 与 due GET 用 `read_security`；start/submit 用 `write_security`。
- **headless**：engine 层不依赖 routes/app（本批次不改 engine）。
- **复审守护**：`tests/test_governance.py::test_governance_zero_ddl` 断言 `count_user_objects == 16` 必须仍通过；本批次新增 `tests/test_web_m10b2.py::test_zero_ddl_after_review_features` 专门守护。

## 3. 验收（AC）

- **AC1**：`GET /review`（激活项目）→ 200；列出到期复测（概念名 + 开始按钮 + 面板锚点）；无激活 → 「尚未选择项目」。
- **AC2**：`GET /api/v1/reviews/due` → 200；返回到期复测列表（含 concept_id / concept_name）。
- **AC3**：`POST /api/v1/reviews/{id}/start` → 200；返回 review_id / attempt_id（草稿卷已建，不绑单元）。
- **AC4**：`POST /api/v1/reviews/{id}/submit`（score∈[0,1]）→ 200；`wrote_to_current_unit` 恒 False（隔离），concept 准确率随 score 更新（≥阈值→已验证）。
- **AC5**：错误路径——条目不存在/已完成 → A060001（HTTP 200）；缺 score 或越界 → C400001（HTTP 400）。
- **AC6**：零 DDL（`count_user_objects == 16` 仍成立）；新增 13 例测试覆盖 AC1–AC6。
