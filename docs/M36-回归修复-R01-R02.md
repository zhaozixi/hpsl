# M36 回归修复：R-01 / R-02

> 本条是 M36 复读（`3829296` 之后）发现的回归修复，不动 M36 已交付的功能面，只校正两处「代码没跟上自己的结论」。

## 背景

M36 收尾提交 `3829296` 把严格 CSP、结构化三问、自动三模型交叉验证落到了代码里。复读时逐行回码，发现两处自相矛盾：

| 编号 | 问题 | 性质 |
|---|---|---|
| R-01 | 创建项目失败（重名 / 校验失败）时，用户已填的名称与目标被清空 | 体验回归，M36 报告 §6 第 3 条经验自己写了「业务错误 200 让 `successful` 失去意义」，代码里仍拿它判成败 |
| R-02 | 同域「单元不存在」有两套错误码：`multi.py` 抛 `C400001`（400，参数校验），`unit.py` / `grading.py` / `state.py` / `providers.py` 抛 `A020001`（200，M2 单元域） | 契约不一致，且被 `test_auto_cross_check_unknown_unit` 固化进测试 |

## 修复

### R-01：把成败判据从 `successful` 换成服务端片段

`hpsl/static/app.js` 的 `htmx:afterRequest` 委托：

```js
if (!(evt.detail && evt.detail.successful)) return;
// 业务错误也返回 200，successful 不足以判定成败；只认片段里的 data-project-id
var box = document.getElementById('result');
var created = !!(box && box.querySelector('[data-project-id]'));
if (created && el.reset) el.reset();
```

选择「读片段」而不是「让 `hpslAfterCreate()` 回传布尔」：`app.js` 不该依赖页面内联函数的返回值，片段本身就是服务端唯一权威。

### R-02：`multi.py::_unit` 统一到 `A020001`

同域四个模块（`unit.py::_get_unit`、`grading.py`、`state.py`、`providers.py`）早已用 `A020001`，`multi.py` 是唯一的例外。修正方向取多数派，避免动一大片既有断言。

**行为变化**：该错误的 HTTP 状态由 `400` 变为 `200`。这是 `A020001` 在基线错误码表里的既定映射（`errors.py`），与 `A020001` 其余调用点一致；客户端判据是响应体 `code`，不是状态码。

测试只改一处取值：`test_auto_cross_check_unknown_unit` 的 `C400001` → `A020001`，并在注释里写清「同域统一」的理由。其余 `C400001` 断言（缺字段、空白、超长、只有 1 家 provider、缺 question）不动 —— 那些确实是参数校验。
