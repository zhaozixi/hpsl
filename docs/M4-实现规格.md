## 1. M4 目标与定位

M4 = 锁定基线 **F8（模型接入与密钥 / BD-7 模型与治理域）+ F6（判定与闭环 / BD-4，判分协议部分）** 的后端引擎落地。把"Provider 适配（httpx 直连 + supports_json 差异隔离；M4 当期为 OpenAI 兼容 + Anthropic 双 Provider 适配器 + Gemini 占位，M22 扩展为 8 家厂商）+ 密钥管理（keyring 优先 / Fernet+Argon2id 降级）+ 判分协议与 JUDGE 闭环门控 + 六角色 LLM 接线（复用 M3 C-04 契约）"实现为**无界面引擎层**（headless）。

**M4 在里程碑链的位置**（M0/M1/M2/M3 交付报告 §8 一致）：M2 的 `state.move()` 使 `JUDGE→INTEGRATE` 合法但未落实判分逻辑——**JUDGE 闭环门控在此里程碑（M4）落实**。

**与 M0–M3 的衔接（已核实，必须沿用）**：
- `common/enums.py`：`Role`（六角色）、`AttemptKind`（重述/边界/追问/复测）、`UnitState`（含 JUDGE/INTEGRATE）。
- `common/errors.py` 已注册 M4/M5 专属错误码：`A040001`（Provider 调用失败重试耗尽）、`A040002`（备选模型未配置）、`A040003`（密钥缺失或无效）、`A040004`（模型响应结构化解析失败）、`A050002`（关键卡点挑错未清零不可闭环）、`A050003`（强行闭环缺少理由）、`A050004`（确认得分缺失不可闭环）。HTTP 语义均为业务失败（200 + `fail(code)`）。
- `hpsl/models/` 现有 `__init__.py` + `README.md` 占位（M0 仅占位，M4 落地）。
- M3 的 `roles/` 包（contracts + assembler）已就位，M4 复用其 C-04 Shared Kernel 组装角色输入，保证**隔离**在 LLM 接线层不破坏。
- 错误码空间纪律：M4 用 `A04xx`、M5 用 `A05xx`（判分相关 A050002/3/4 已在 M4 落实判分逻辑时承载）；M1 用 C 类码（Web 安全）；M2 用 A02xx；M3 用 A03xx。

## 2. 范围边界

### 2.1 In-Scope（M4 必须交付）

1. **Provider 适配 `models/base.py` + `models/openai_compat.py` + `models/anthropic.py` + `models/gemini.py`（占位）**
   - `base.py`：`Msg` / `Reply` 数据类 + `ProviderAdapter` 协议（防腐层 BC-7）。
   - `openai_compat.py`：`OpenAICompatAdapter`（E-01，OpenAI / DeepSeek 等）——httpx 直连；`supports_json=true` 走 `response_format` 原生结构化；固定模型 ID；超时/重试（指数退避 1s/2s，最多 2 次）；重试耗尽 → `A040001`；备选切换由调用方/CLI 明示（不静默）。
   - `anthropic.py`：`AnthropicAdapter`（E-02）——`supports_json=false` 走 tool-use 等价路径（结构化退化为「解析 + 校验 + 重试」，失败 → `A040004`）。
   - `gemini.py`：v1 占位，仅抛 `NotImplementedError`（O7，本期不实现）。
2. **模型注册与异构判定 `models/registry.py` + `models/models.yaml` + `models/pricing.yaml`**
   - `registry.py`：读取 `models.yaml` → `ModelConfig`（provider / family / derived_from / supports_json / is_fallback_for）；`heterogeneous(a, b)` 判定（family 或 derived_from 相交即非同源）。
   - `models.yaml`：模型清单（主力 E-01 + 第二厂商 E-02 备选，含 family / derived_from / supports_json）。
   - `pricing.yaml`：价格表（用户可维护，D1 §7.5）。
3. **密钥管理 `secrets/keystore.py`（F8.2）**
   - `get_api_key(provider)`：keyring 优先（三平台后端），不可用时降级 Fernet 加密文件（0600）+ Argon2id 口令派生（RFC 9106 参数，随机 salt；口令内存派生不落盘）。
   - `set_api_key(provider, key)` / `key_status(provider)`（仅后 4 位 + 存储位置）；密钥禁入日志/VOC/导出。
4. **判分协议与 JUDGE 闭环门控 `engine/grading.py`（F6 判分协议）**
   - `evaluate_close(pid, uid, confirmed_score, *, force_close, close_reason) -> CloseDecisionVO`：达标判定（`confirmed_score ≥ config.pass_threshold`，默认 0.7）、关键卡点例外（claim_check 残留实质错误 → `A050002`）、强行闭环理由必填（force_close 且 reason 空 → `A050003`）、确认得分缺失（confirmed_score 为 None → `A050004`）。
   - `close_unit(pid, uid, confirmed_score, *, force_close, close_reason)`：经 `evaluate_close` 判定后写 `unit.closed_at`/`forced_close`/`close_reason` 并 `state.move(JUDGE→INTEGRATE)`（全部经 `db.write`，同事务审计）；`forced_close=1` 不计入进度（M9 统计剔除）。
5. **六角色 LLM 接线 `engine/role_llm.py`（复用 M3 C-04）**
   - `RoleLLM.complete(role, context, *, stream=False) -> Reply`：经 `assembler.assemble`（M3 白名单，**隔离不可破坏**）取角色可见字段 → 由 `roles/prompts/*.md` 拼装 system 提示词 → `adapter.complete` 调用 → 返回 `Reply`。保证 answer_machine_output 等隔离字段绝不在组装层外泄漏。
6. **测试**：`tests/test_models.py`（适配器请求构造/解析 + heterogeneous + 重试/备选 + keystore Fernet 路径）、`tests/test_grading.py`（要点隐藏 + 强行闭环理由必填 + 关键卡点阻断 + 达标闭环，关键模块）、`tests/test_role_llm.py`（角色接线 + 隔离保持）。
7. **回归**：M0/M1/M2/M3 既有 77 测试仍全绿（AC-M4-8）。

## 4. 接口契约（引擎内部 API，权威见基线 §3.2.M4 / §3.2.M5 / §3.5.1）

### 4.1 Provider 适配（BC-7 防腐层，基线 §3.2.M4）

```python
# models/base.py
@dataclass(frozen=True)
class Msg:
    role: str          # system / user / assistant
    content: str

@dataclass(frozen=True)
class Reply:
    text: str
    finish_reason: str     # stop / length / error
    model: str
    raw: dict | None = None

class ProviderAdapter(Protocol):
    name: str
    def complete(self, messages: list[Msg], *, json_schema=None, stream: bool = False) -> Reply: ...
```

- `OpenAICompatAdapter(name, base_url, model_id, *, key_resolver, supports_json=True, timeout=30.0, max_retries=2)`：
  - `complete`：构造 `POST {base_url}/chat/completions`；headers 含 `Authorization: Bearer <key_resolver()>`、`Content-Type`；body 含 `model`、`messages`、`response_format`（supports_json 时）或 tool 等效；`stream` 时走 SSE（M4 仅实现非流式，流式留钩子）。
  - 网络错误 / 5xx / 429 → 指数退避重试（1s / 2s，最多 `max_retries`）；重试视为新调用逐次记账（防预算失真）；耗尽 → `A040001`。
  - 解析 `choices[0].message.content` / `finish_reason`；结构化解析失败 → `A040004`。
  - **测试性**：`key_resolver` 与底层 httpx `post` 均可注入（缺省用 `secrets.get_api_key` 与 `httpx`）；测试用 fake `post` 返回 canned `Reply` 或抛异常，验证请求构造、重试、解析、**绝不泄露密钥到日志/VOC**。
- `AnthropicAdapter`：`supports_json=false` → tool-use 等价路径（Messages API），结构化退化为「解析 + 校验 + 重试」，失败 → `A040004`；其余同 OpenAI 适配的超时/重试。
- `registry.heterogeneous(a: ModelConfig, b: ModelConfig) -> bool`：a/b 的 `family` 相交或 `derived_from` 相交 → `False`（同源），否则 `True`。

### 4.2 密钥管理（基线 §3.2.M4 / §7.2.3）

- `secrets/keystore.py`：
  - `get_api_key(provider) -> str`：`keyring.get_password("hpsl", provider)` 优先；不可用（或 keyring 抛异常 / 返回 None）→ Fernet 加密文件（路径 `secrets/<provider>.fernet`，权限 0600），内容由 Argon2id 派生密钥 + Fernet 解密；均无 → `A040003`。
  - `set_api_key(provider, key)`：keyring 可用则 `set_password`；否则 Fernet 加密写入文件（0600）。
  - `key_status(provider) -> dict`：`has_key`、`stored_in`（`keyring` / `fernet_file`）、`key_tail`（后 4 位）；完整密钥**禁止**入任何 VO / 日志 / 导出。
  - Fernet 口令：Argon2id（RFC 9106 推荐参数 + 随机 salt）派生；口令由用户启动输入，内存派生不落盘（M4 测试注入口令或跳过 keyring 走 Fernet 文件，保证 headless 可测）。
  - **测试性**：`secrets_dir` 可注入（默认 `hpsl/secrets/` → 测试用临时目录）；keyring 不可用时自动走 Fernet 路径，Fernet 加解密往返 + 权限 + 缺失密钥 → `A040003` 全测。

### 4.3 判分协议与闭环判据（基线 §3.2.M5 / §9.3）

- `engine/grading.py`：
  - `evaluate_close(pid, uid, confirmed_score, *, force_close=False, close_reason=None) -> CloseDecisionVO`：
    - `confirmed_score is None` → `A050004`（确认得分缺失，不可闭环）。
    - `unit.status != 'JUDGE'` → 拒绝（非 JUDGE 不可闭环，可复用 `A020001` 或新语义，M4 取 `A050004` 上下文拒绝；实现以"仅 JUDGE 可评估闭环"守卫）。
    - 关键卡点：`has_unresolved_keypoint(pid, uid)`（查 `claim_check` 表；表不存在或无关 → False）→ 若有未清零实质错误 → `A050002`。
    - 达标：`passed = confirmed_score >= config.pass_threshold`（默认 0.7）。
    - `force_close and not close_reason`（空/None）→ `A050003`（强行闭环缺少理由）；`close_reason` 超 500 字符 → 拒绝（参数校验）。
    - 返回 `CloseDecisionVO(close_allowed, forced, passed, pending_residual, reason=None)`：
      - `passed and not force_close` → `close_allowed=True, forced=False`；
      - `not passed and force_close and reason` → `close_allowed=True, forced=True`；
      - 其余 → `close_allowed=False`（由调用方据 reason 决定回补 LEARN 或提示）。
  - `close_unit(pid, uid, confirmed_score, *, force_close, close_reason) -> UnitStateVO`：经 `evaluate_close` 校验 → `db.write(unit, {closed_at, forced_close, close_reason})`（forced_close=1 当 force_close）→ `state.move(JUDGE→INTEGRATE)`；全部经 `db.write` 同事务审计；返回新状态 VO。
  - `has_unresolved_keypoint(pid, uid)`：防御性查 `claim_check`（`SELECT count(*) FROM claim_check WHERE unit_id=? AND resolved=0`）；表不存在 → 返回 False（M4 不强制建 claim_check，F7/M5 建）。
- `pass_threshold` 取自 `projects.get_effective_config(pid).pass_threshold`（默认 0.7，待校准）。

### 4.4 六角色 LLM 接线（复用 M3 C-04，基线 O13）

- `engine/role_llm.py`：
  - `RoleLLM(adapter, assembler=assembler, prompts_dir=...)`：
  - `complete(role, context, *, stream=False) -> Reply`：
    1. `fields = assembler.assemble(role, context)` —— **隔离强制**：仅 allow 字段，answer_machine_output 等绝不可见；
    2. `system_prompt = build_prompt(role, fields)`（读 `roles/prompts/{role}.md` 骨架 + 注入可见字段，**绝不注入 allow 外字段**）；
    3. `messages = [Msg("system", system_prompt), Msg("user", <学习者输入或汇总>)]`；
    4. `return adapter.complete(messages, stream=stream)`。
  - 隔离断言：单元测试须验证 answer_machine_output 即便在 context 中存在，也**不出现在**发送给模型的 messages 中（复用 M3 哨兵精神）。

## 6. 实现注意

- **不引入 ORM**：SQL 全部手写，复用 M0 `db.write` 唯一写入入口；审计自动附随。
- **不改动基线文档**：实现只在新建 `models/` / `secrets/` / `engine/grading.py` / `engine/role_llm.py` 与 `tests/`；`delivery/` 已通过 CHG-02 对齐，M4 不触碰。
- **headless**：`models` / `secrets` / `engine/*` 不依赖 `routes` / `app`，便于 M10 接入与 headless 测试；真实网络调用经注入 fake 测试，不要求测试环境有 key / 联网。
- **错误码**：M4 专用 `A04xx` / 判分相关 `A050002/3/4`（已在 `errors.py` 注册），直接 `raise BizError("A04xxx")`；不得新增冲突码。
- **密钥红线（D1 §6.5）**：完整 API 密钥禁止入日志 / VO / 导出；`key_status` 仅暴露后 4 位。
- **隔离红线（O13）**：role_llm 必须经由 `assembler.assemble`，绝不直取 context；答案机输出不回流任何消费角色。
- **重试记账（防预算失真）**：重试视为新调用逐次记账（M4 仅留钩子 `cost.record_call`，完整成本治理属 M8）。
- **不静默切换（BD-01）**：备选模型切换须由调用方/CLI 明示，适配器不自行静默切换；M4 适配器暴露 `is_fallback_for` 与备选选择由上层决定。
