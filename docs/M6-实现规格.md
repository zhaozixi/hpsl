## 1. M6 目标与定位

M6 = 锁定基线 **§3.2.M6 延迟复测队列模块（BD-6）** 的后端引擎落地，**对齐"延迟复测"核心域**。

**范围边界（关键澄清）**：UserStory 中标注 "v1（M6）" 的 O4–O7（多模型挑错 / 三异构答案机 / Gemini 接入等）是 **v1 功能的排期标签**，并非 M6 里程碑本身。系统设计 §3.2 权威口径明确 **M6 = 延迟复测队列（BD-6）**。M5 之后的下一个构建模块即本里程碑。

**承接已核实资产（必须沿用）**：
- M2 已实现复测队列**核心引擎**：`REVIEW_INTERVALS=(2,7,21)`、`enqueue_reviews`（幂等入队）、`due_reviews`（读时到期计算）、`submit_review`（概念级提交 + 写回隔离 + 不变量）、VO（ReviewItemVO / ReviewResultVO / ReviewSubmitRequest）；错误码 `A060001` 已在 `common/errors.py` 注册。
- M0 锁定的 16 库对象中，`review`(id/concept_id/attempt_id/kind/due/result) 与 `attempt`(id/unit_id/concept_id/kind/rubric/self_score/confirmed_score/seconds/ts) **已含全部所需列**，M6 零新增 DDL。
- 纪律红线（全程沿用）：密钥红线（D1 §6.5）、隔离红线（O13：复测 attempt 绝不绑定 unit，当前单元账本零写入）、错误码分段（M6 = A06xx）、headless 不依赖 routes/app、所有写仅经 `db.write` 同事务审计。

**M6 NEW（本里程碑增量）**：
- `start_review(pid, review_id, *, question=None) -> ReviewStartVO`：开始复测（生成复测卷），幂等单活跃卷（草稿 attempt 复用），返回复测卷视图。
- `ReviewStartVO`：复测开始视图对象。
- `submit_review_by_id(pid, review_id, score, *, seconds, actor) -> ReviewResultVO`：按 review_id 精确提交，草稿卷复用 + 写回隔离 + 不变量。
- `submit_review(pid, concept_id, ...)`：保留 M2 概念级入口作为向后兼容，内部分派到 `submit_review_by_id`。
- Q1 纪律断言测试：误写当前单元 0 条、写回概念准确率、单活跃卷幂等。

## 2. 范围边界

### 2.1 In-Scope（M6 必须交付）

1. **开始复测 · 复测卷生成（§3.2.M6.2 内部 API `start_review`）`engine/review_queue.py`**
   - `start_review(pid, review_id, *, question=None) -> ReviewStartVO`：校验 review 存在且活跃（result IS NULL），否则 `A060001`。
   - 幂等（单活跃卷）：若 `review.attempt_id` 已设（已开始的草稿卷），返回既有 VO，不重复建 attempt。
   - 否则建 `attempt`（kind=复测，concept_id）草稿并回写 `review.attempt_id`（标记「复测中」）。
   - `question` 由 M10 经出题者（BoundarySetter，M3/M4）生成后传入；引擎层 headless 不直连 LLM；`ReviewStartVO.question` 透传，不持久化。
   - 纪律不变量：绝不写 unit/gap/任何当前单元账本。
2. **按 review_id 提交复测（§3.2.M6.2 内部 API `submit_review(review_id, ...)`）`engine/review_queue.py`**
   - `submit_review_by_id(pid, review_id, score, *, seconds, actor) -> ReviewResultVO`：校验 review 活跃（否则 A060001）。
   - 草稿卷复用：若 `start_review` 已建 attempt 且未评分（`confirmed_score` IS NULL），则更新之；否则新建。
   - 写 attempt（kind=复测，confirmed_score=score，不绑 unit）+ concept（verify_status / last_verified_at，仅两字段）+ review 保持活跃并推进 due（result 维持 NULL，2→7→21→21 循环；attempt_id 回写 review）。
   - 纪律不变量：`wrote_to_current_unit` 恒 False。
   - `submit_review(pid, concept_id, ...)`：M2 概念级入口保留，内部分派 `submit_review_by_id`（向后兼容 + 测试）。
3. **写回纪律（§3.2.M6.5 设计不变量）**：复测只写被复测 concept 的 `verify_status`/`last_verified_at` + `attempt`（kind=复测）定稿 + `review` 保持活跃仅推进 `due`；`wrote_to_current_unit` 恒 false 并显式返回供断言；复测结果以 `attempt` 为准。
4. **复测队列状态机（§3.2.M6.5 迁移表）**：待复测(2d) → 到期(可作答) → 复测中 → 已完成(next 档) → ... → 21d 循环；独立于单元状态机，不占用单元状态。
5. **导出补齐**：`engine/__init__.py` 导出 `start_review` / `submit_review_by_id` / `ReviewStartVO`。
6. **测试**：`tests/test_review_queue.py` 新增 8 例（start_review 字段 / 幂等 / 缺失 A060001 / submit_review_by_id 写回隔离 / 缺失 A060001 / 草稿卷复用 / Q1 纪律断言 / 标记复测中）。
7. **回归**：M0–M5 既有 **135** 测试仍全绿（零 DDL、零破坏）。

### 2.2 Out-of-Scope（M6 不做，留待后续）

- **HTTP 路由暴露**：`GET /api/v1/review/due`、`POST /api/v1/review/{rid}/start`、`POST /api/v1/review/{rid}/submit`、`GET /api/v1/review`、`POST /api/v1/units/{uid}/review-enqueue` 属 M10 Web 接入；M6 仅落地引擎原语。
- **首页 UI 编排**：主按钮高亮「做到期复测（≤2 次点击进入作答）」属 M10 交互。
- **真实出题者 LLM 调用**：`start_review` 的 `question` 由 M10 经出题者形态生成后传入；M6 引擎 headless 不直连 LLM。
- **v1 多模型挑错 / O4–O7**：标注 "v1（M6）" 的排期内容属 v1（M6 之后的 v1 迭代），非本里程碑。

## 3. 与锁定基线的偏差与实现决策（须记录）

| # | 偏差/决策 | 原因 | 处理 | 影响 |
|---|-----------|------|------|------|
| D-M6-1 | `ReviewResultVO` 字段命名与基线 §3.2.M6.3 DTO（concept_verify_status / last_verified_at / next_due / wrote_to_current_unit）不完全一致；M2 实现为 concept_id/score/passed/review_id/attempt_id/next_due/wrote_to_current_unit | M2 已锁定该 VO 形状且被 135 套件断言持有；重新对齐基线字段名会破坏既有 M2 测试 | 保持 M2 既有 VO 形状零破坏性；核心不变量 `wrote_to_current_unit` 恒 false 与基线一致 | 零 DDL；兼容 M2 回归绿 |
| D-M6-2 | `submit_review(pid, concept_id, ...)` 保留 M2 概念级入口（向后兼容），M6 主路径为 `submit_review_by_id(pid, review_id, ...)` | 基线 §3.2.M6.2 同时要求「概念级入口」与「review_id 精确提交」两种内部 API；M2 已落地概念级 | M2 概念级入口内部分派 `submit_review_by_id`；M10/测试可按需选用 | 双入口并存，向后兼容 |
| D-M6-3 | `start_review` 增加 `question` 可选参数（默认 None），`ReviewStartVO.question` 透传，**不持久化** | 基线 SQ-M6-01 中复测卷由「出题者 M3/M4」生成（边界题）；引擎 headless 不直连 LLM，question 应由 M10 注入 | 引擎仅透传 question；不新增落库列（符合"出题者形态"边界与零 DDL） | 零 DDL；M10 接入时填充 |
| D-M6-4 | HTTP 路由（/api/v1/review*）与首页 UI 编排留待 M10 | 基线 §3.2.M6.2 接口为 HTTP 路径，但 M6 仅做引擎层；与 M5（路由属 M10）一致 | M6 仅交付 headless 引擎原语 + 测试 | 路由暴露归 M10 |

> 以上偏差均不触及 `db.py` / `routes/` / `app.py` 既有逻辑与 M0 锁定的 16 库对象（零 DDL）。

## 4. 内部 API 与 VO 映射（对齐 §3.2.M6.2）
