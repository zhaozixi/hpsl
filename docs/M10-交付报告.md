## 2. 范围与边界

### 2.1 In-Scope 已交付
1. **`routes/governance.py`**：4 个 REST 端点——`GET /api/v1/counts`、`GET /api/v1/counts/planes`、`GET /api/v1/soft-prompts`、`POST /api/v1/soft-prompts/{id}/dismiss`（写接口走 `write_security`：Origin + CSRF + 限流）。全部只读，零 DDL。
2. **`routes/ledger.py` + `templates/ledger.html`**：`GET /ledger` 渲染四本账（M7 `ledger_summary`）+ 四平面度量（M9 `compute_counts` 12 字段）+ 治理软提示区（htmx POST 一键关闭；整页刷新依 `sid` cookie 过滤，与写接口共享 `_dismissed`）。
3. **`routes/security.py`**：新增 `new_trace_id()`（32 位 hex）+ `TraceIdMiddleware`（读 `x-trace-id` 或生成，置 `request.state.trace_id`，响应头回写 `X-Trace-Id`）。
4. **`db.py`**：新增 `close_all()`（非 DDL，遍历关写连接隐含 WAL checkpoint），供优雅停机钩子。
5. **`app.py`**：挂载 governance/ledger 路由；`TraceIdMiddleware` 最外层包裹 → `SecurityMiddleware`；新增 `/readyz`（纯探测，可读写 200 否则 503）；`BizError` 异常处理器携带 traceId；`serve()` 改用 `uvicorn.Server(timeout_graceful_shutdown=30)` + `atexit.register(db.close_all)`。
6. **`static/app.css`**：账本总览 grid/card/prompt/badge/notice 样式。
7. **测试**：`tests/test_web_m10.py`（10 例）。

## 3. 与锁定基线的偏差与实现决策（须记录）

| # | 偏差/决策 | 原因 | 处理 | 影响 |
|---|-----------|------|------|------|
| D-M10-1 | `/readyz` 为纯探测，不自动创建 `projects_root` | readiness 不应有写副作用；目录由首个项目创建 | 测试先建项目再断言 200 | 严格对齐锁定基线 |
| D-M10-2 | 软提示关闭 v0 用进程内 `_dismissed` 字典 + `sid` cookie，非持久 | M9 仅输出，持久化（落 audit_log/config）留后续 | 文档标注，重启清空 | 功能可用；持久化留后续 |
| D-M10-3 | `/ledger` 页面渲染按 `sid` cookie 过滤已关闭软提示，与写接口共享 `_dismissed` | 使整页刷新后关闭状态一致 | `ledger.py` 自 `governance` 导入 `_dismissed` / `SID_COOKIE` | 路由间共享进程内状态（单机本地形态可接受） |
| D-M10-4 | 重业务页面 / 备份导出 / 卡片概念图 UI 留 Phase B/C | 控制 M10 范围，先打通治理度量接入 | 后续里程碑 | 范围收敛 |
| D-M10-5 | 中间件顺序修正：`TraceIdMiddleware` 置于最外层 | Starlette 语义「最后添加者最外层」；原写法是 Security 在外、TraceId 在内，导致 Host 拒绝响应（C400003）缺 `X-Trace-Id`，与「贯穿全程」声明不符（独立验证 Agent 发现，低危、非纪律违规） | 交换 `add_middleware` 顺序 + 修正注释 + 同步规格 §3 | 拒绝路径同样可观测；全量套件仍 200 passed + 1 skipped |

> D-M10-1~4 不破坏 M0 锁定的 16 库对象（零 DDL 已实测验证）；D-M10-5 仅调整中间件包裹顺序，无 DDL/无新码。

**风险/发现（已闭环）**：
- **[低危，已修正] 中间件顺序不符声明**：原 `app.py:35-36` 先加 TraceId 后加 Security，而 Starlette「最后添加者最外层」→ Security 实际在外，Host 被拒（C400003）响应缺 `X-Trace-Id`。独立验证实测确认该偏差。本回合已交换 `add_middleware` 顺序使 TraceId 最外层（D-M10-5），拒绝路径现亦回写 `X-Trace-Id`；规格 §3 与注释同步修正；全量复跑仍 200 passed + 1 skipped。
- **[既有，非 M10 引入]** `security.py:9-11` docstring 自陈 C 类码复用与 M1 §2.1 A02xx 分配冲突，「已上报主理人裁决」，非 M10 新引入。

**结论**：M10 满足全部锁定纪律约束；测试全绿；唯一实质偏差（中间件顺序）已修正。无 BLOCKER。
