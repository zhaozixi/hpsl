## 3. 两项冲突裁决与落实确认

- **(1) Windows 0700**：实现用 `mkdir(mode=0o700)+os.chmod(0o700)`（projects.py:121-122），测试对 `os.name=='nt'` 自适应断言。本机 win32 实测 stat 模式 0o777（Windows 不表达 POSIX 权限位），单机单用户、家目录默认 owner-only，实际隔离满足。**接受**为已知跨平台注意项，不引入 ctypes NTFS DACL 硬编码（M0）。
- **(2) project 表无 name 列**：name 存于 `project.config` JSON 的 `name` 键；创建时扫描各项目目录读 `config.name` 判重（projects.py:61-82）；`ProjectVO.name` 由 config 还原。与冻结 DDL §7.1 注释及规格 §4「项目名唯一性由 projects.py 扫描项目根目录实现」逐字一致。**确认**此存储约定，M1 接口层对 name 透明读取即可。

## 4. 缺陷与风险清单（无致命/严重，均未因进度下调）

| 编号 | 级别 | 标题 | 处置建议 | 排期 |
|------|------|------|---------|------|
| D1 | 一般 | 单写连接无线程锁，多线程并发写可能交错 | `_write_conns` 按 pid 缓存单例但 `check_same_thread=False`，write/undo 事务体未加 `threading.Lock` | **M10 前必须闭环**（uvicorn 线程池跑同步 DB 调用上线前需加每 pid 写锁） |
| D2 | 轻微 | 项目名唯一性 TOCTOU（先扫描后创建，无跨进程锁） | 多进程部署时加文件锁/原子占位 | 多进程部署前 |
| D3 | 轻微 | JSON 列写入未校验合法性，读取静默吞错 | 写入端校验或读取端明确告警 | 后续增强 |
| D4 | 轻微 | write 仅校验 id 必填，未校验其它 NOT NULL 列 | 增必需列校验或捕获 IntegrityError→C400001 | 后续增强 |
| D5 | 轻微 | undo 直接信任 audit_log.table_name 拼 SQL | undo 入口加 `table_name in TABLES` 防御断言 | 后续增强 |
| D6 | 轻微 | 读连接未以只读标志打开 | get_read_conn 用 SQLITE_OPEN_READONLY | 防御纵深 |

> 以上均不阻塞 M0 发布。D1 已同步开发成员高建瓴作为 M10 前跟踪项。

## 5. 遗留问题与风险

- **跨平台权限**：AC1 在 Windows 仅达到"实现正确调用 + 自适应断言"，非严格 POSIX 0700；若未来要求 Windows 也达 owner-only，需 ctypes 设置 NTFS DACL（待定，非 M0 阻塞）。
- **并发模型**：M0 为单进程同步调用，单写连接串行成立；**M10 Web 层上线前必须补 D1 写锁**，否则线程池并发 write 共享连接会触发 cursor 交错/嵌套 BEGIN 的 SQLITE_BUSY。
- **测试覆盖**：test_security/grading/cost/contracts 四类守护按基线 §11 留待对应里程碑补全，不计入 M0 门禁。
