## 1. M3 目标与定位

M3 = 锁定基线 **F3（角色与隔离）/ BD-3（角色与隔离域）/ BC-3（角色隔离上下文）** 的后端引擎落地。把"六角色契约 + 白名单组装器 + 输入预览 + 隔离自动测试"实现为**无界面的引擎层**（`roles/contracts.py` + `roles/assembler.py`），作为 Shared Kernel（C-04）供未来判分域（M4/M5）复用。

**核心卖点（基线 O13）**：本系统是"角色隔离"学习治理工具——每个 LLM 角色只能看到自己契约 `allow` 白名单内的字段。**答案机输出（`answer_machine_output`）永不流入任何消费角色**（出题者 / 提问者 / 挑错者 / 选题 / 书记员），避免同源污染与确认偏误。这是产品差异化护城河，M3 必须以可断言的方式固守。

**与 M0/M1/M2 的衔接（已核实，必须沿用）**：
- `common/enums.py` 已有 `Role` 枚举：`USER / ANSWER_MACHINE / QUESTIONER / BOUNDARY_SETTER / CRITIC / CLERK / TOPIC_PICKER`。**六角色** = 后六项（`USER` 为自然人学习者，不在此列）。
- `common/errors.py` 已注册 M3 专属错误码 `A030001`（契约越界：角色读取未授权字段），HTTP 语义为业务失败（200 + `fail(code)`）。
- M0 的 `db.write` 审计、M1 的 Web/安全、M2 的状态机/复测队列均不涉及 `roles/`，M3 零冲突。
- 错误码空间纪律：M3 用 `A030001`；M1 已用 C 类码（C400003/C403001/C429001）承接 Web 安全；M2 用 A02xx；互不占用。

## 2. 范围边界

### 2.1 In-Scope（M3 必须交付）

1. **六角色契约 `roles/contracts.py`（Shared Kernel，C-04）**：
   - 规范上下文字段常量（"数据湖"键名，见 §4.1）。
   - `CONTRACTS: dict[Role, RoleContract]`，六角色各一条；`allow` 为**固定顺序元组**（非 set/list），保证组装顺序稳定与可断言。
   - `RoleContract` 含 `role` / `allow` / `description`。
   - 隔离不变量函数 `_invariant_answer_isolated()`：`answer_machine_output` 不在任何消费角色 allow 中（契约层哨兵）。
2. **白名单组装器 `roles/assembler.py`**：
   - `assemble(role, context, *, requested=None) -> dict`：仅返回 `allow ∩ context`，按 `allow` 固定顺序；若 `requested` 给定且含 allow 之外字段 → `A030001`（越权）；纯函数，不修改 context。
   - `preview(role, context) -> dict`：返回角色可见内容的稳定预览（F3.3 输入预览，默认收起由 M10 控制），不泄露 allow 之外字段。
3. **`roles/prompts/` 六角色提示词骨架（占位）**：六个最小系统提示词模板（answer_machine / questioner / boundary_setter / critic / clerk / topic_picker），供 M4/M7 接入 LLM 时填充；M3 不接线 LLM、不读 models/ 适配器。
4. **测试 `tests/test_role_isolation.py`（AC-M3-1~7 + 隔离强断言）**。注：顶层 `tests/test_isolation.py` 已被 M2 时代的"DB/写入隔离纪律"哨兵占用（属回归套件），M3 角色隔离测试改用 `test_role_isolation.py` 避免同名碰撞。
5. **回归**：M0/M1/M2 既有 65 测试仍全绿（AC-M3-6）。

### 2.2 Out-of-Scope（M3 不做，留待后续）

- **Phase 2 视觉 / Phase 3 交互**：M3 为无界面引擎模块，不涉及 UI/交互设计，按 SOP 范围冻结原则跳过。
- **LLM 真实调用 / Provider 适配 / 密钥管理**：归属 **M4（模型适配）/ M7（模型与治理）**。M3 仅定义契约与组装，不 import `models/`、不发起 httpx 请求。
- **判分域（F5/F6）对契约的复用**：C-04 Shared Kernel 已就位（contracts.py 为常数模块），但判分域落实在 M4/M5。
- **六角色自动分配模型**：归属 M4/M7（BD-7），M3 不实现。
- **HTTP 路由暴露**（角色预览端点等）：归属 **M10 Web 接入**。

## 4. 接口契约（引擎内部 API，权威见基线 §3.2 / F3）

### 4.1 规范上下文字段（数据湖键名）

| 常量 | 键名 | 含义 |
|---|---|---|
| CTX_UNIT_TITLE | `unit_title` | 单元标题 |
| CTX_DIFFICULTY | `difficulty_band` | 难度带 |
| CTX_CONCEPT_SUMMARY | `concept_summary` | 概念账本摘要 |
| CTX_TOPIC | `topic` | 当前选题 |
| CTX_PRIOR_QA | `prior_qa` | 已有问答历史 |
| CTX_RESTATEMENT | `learner_restatement` | 学习者重述（三问） |
| CTX_RUBRIC | `rubric` | 评分要点（边界题评分标准） |
| CTX_PRODUCTION | `learner_production` | 学习者产出 |
| CTX_ANSWER | `answer_machine_output` | 答案机输出（**隔离保护对象**） |
| CTX_TRANSCRIPT | `conversation_transcript` | 对话转录 |
| （局部） | `question` | 答案机接收的问题（仅答案机 allow） |

### 4.2 六角色契约 `allow` 元组（固定顺序，隔离关键）

| 角色 | allow（固定顺序） | 隔离要点 |
|---|---|---|
| TOPIC_PICKER 选题 | `(unit_title, difficulty_band, concept_summary)` | 基于账本摘要选题，不见答案机输出 |
| ANSWER_MACHINE 答案机 | `(unit_title, topic, question)` | 仅接收学习者问题，自身产出 `answer_machine_output` |
| QUESTIONER 提问者 | `(topic, learner_restatement, prior_qa)` | 基于重述递进追问，禁止给答案（不见答案机输出） |
| BOUNDARY_SETTER 出题者 | `(topic, learner_restatement, rubric)` | 基于重述+评分要点命制边界题（**不见答案机输出**） |
| CRITIC 挑错者 | `(topic, learner_production, concept_summary)` | 独立评判产出（**不见答案机输出**，避免同源偏误） |
| CLERK 书记员 | `(conversation_transcript, unit_title)` | 从转录抽取候选缺口 |

> **隔离不变量（哨兵，C-04 / AC-M3-4）**：`answer_machine_output` 不在**任何**角色的 `allow` 中（答案机自身产出它，但也不"读取"它；所有消费角色均不包含）。`assemble` 即使 context 含该字段，对任一消费角色组装时也绝不出现。

### 4.3 组装器语义

- `assemble(role, context, *, requested=None)`：
  - `role`：接受 `Role` 枚举或字符串（"clerk" / "CRITIC" 均可），归一为 `Role`；未知角色 → `A030001`。
  - `requested=None`：返回 `allow ∩ context`，按 `allow` 固定顺序；context 中其余字段（含 `answer_machine_output`）一律剔除。
  - `requested` 给定：先校验 `requested` 每项 ∈ `allow`，任一越界 → `A030001`（"角色 X 越权读取未授权字段：[...]"），**无副作用**；校验通过后返回 `requested ∩ context`（按 requested 顺序）。
  - 允许字段在 context 中缺失 → 该键不出现于输出（宽松：仅缺失不报错；越权才报错）。
- `preview(role, context) -> dict`：返回 `{role, description, allowed_fields, visible_fields, visible_values}`，供 M10 输入预览（默认收起）；`visible_fields` 必为 `allowed_fields` 子集，绝不含隔离外字段。

## 6. 实现注意

- **不引入 ORM / 不触库**：M3 纯内存契约与组装，不 import `db`、不读写 SQLite。
- **不改动基线文档**：实现只在新建 `roles/` 与 `tests/`；`delivery/` 已通过 CHG-02 对齐，M3 不触碰。
- **headless**：`roles` 不依赖 `models/` / `routes` / `app`，便于 M4/M7 接入与 headless 测试。
- **错误码**：M3 专用 `A030001` 已在 `errors.py` 注册，直接 `raise BizError("A030001")`；不得新增 A03xx 之外的冲突码。
- **顺序纪律**：`allow` 必须用元组（有序），供 `visible_fields` 渲染与哨兵断言稳定。
- **隔离强断言**：`test_isolation` 须显式断言 `BOUNDARY_SETTER` / `CRITIC` / `QUESTIONER` 在 context 含 `answer_machine_output` 时组装结果不含该键；并断言 `assemble` 不修改入参 context（无副作用）。
