## 1. 背景与范围

v0 的引擎原语（状态机 / 判分 / 复测 / 记账）都已落地，但**没有生产调用方**：界面无法建单元、六角色无法被调用、`llm_call` 无写入、`review` 行无创建。本里程碑只做一件事——**把主链接通**，让"建单元 → 产出 → 记录尝试 → 闭环 → 到期复测"与"角色调用 → 记账"成为可用路径。

**In-Scope（P0-A，本批）**

| # | 能力 | 端点 |
|---|---|---|
| 1 | 建单元（INIT） | `POST /api/v1/units` |
| 2 | 提交产出（回归主线） | `POST /api/v1/units/{uid}/production` |
| 3 | 记录尝试（重述/边界/追问/复测） | `POST /api/v1/units/{uid}/attempts` |
| 4 | 闭环 + 自动入队复测 | `POST /api/v1/units/{uid}/close` |
| 5 | 六角色调用 + 记账 | `POST /api/v1/roles/{role}/call` |

**Out-of-Scope（P0-B/C，后续）**

- `/unit` 与 `/unit/{uid}` 的表单（UI）；
- 显式会话端点（`POST /units/{uid}/sessions`、`POST /sessions/{sid}/end`）；
- 写 `turn` 表（INTEGER PK 与 `db.write` 强制带 id 的冲突，需在写锁内取 `max(id)+1`）；
- 选题三候选、rubric 生成的界面时序、A050001 界面守卫；
- 安全四件套（P0-05~08，需先定"改代码还是改文档"）。

## 2. 纪律约束（硬）

1. **零 DDL**：16 库对象不变，`count_user_objects == 16` 由测试守护；
2. **唯一写入口**：全部写入经 `db.write`（含 `session` / `attempt` / `unit` / `llm_call`）；
3. **隔离不破**：角色上下文只经 `assembler.assemble`，`answer_machine_output` 永不入 messages；
4. **不新增错误码**：复用 A010001 / A020001 / A030001 / A040001 / A040003 / A050002~4 / C400001；
5. **状态推进唯一入口**：仍只经 `state.move`，新端点不直接改 `status`；
6. **engine headless**：`role_llm.call_role` 不依赖 FastAPI / routes。

见 [PLAN-P0 §3](PLAN-P0-主链最小闭环.md)。实现与方案一致，仅一处补强：

## 6. 风险

| 风险 | 缓解 |
|---|---|
| `record_call` 依赖进程级 active 项目 | 端点一律从 `active_project()` 取 pid；多项目并发不在 v0 范围 |
| 自动选模型可能选到 Gemini（占位） | `pick_default_model` 跳过 `provider_kind == "gemini"` |
| 记账失败导致"白跑" | 调用成功但记账失败会抛错（同事务语义）；P1 再评估降级策略 |
| 复测依赖 `attempt.concept_id` | 为空则不入队（返回 0），不阻塞闭环 |
