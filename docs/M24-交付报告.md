## 2. 关键实现决策（与 PLAN 的差异）

| 编号 | 决策 | 理由 |
|---|---|---|
| D-M24-1 | 复测入队放在**路由编排层**（`close` 端点），不改 `close_unit` 返回值 | `UnitStateVO` 被既有测试按形状断言，改签名会波及 M2/M4 用例；入队失败也不应影响已完成的闭环 |
| D-M24-2 | `enqueue_unit_reviews` 的 `closed_at` 缺省**读 `unit.closed_at`** | 保证 `due = closed_at + 2d` 精确；若用入队瞬间会有毫秒级漂移 |
| D-M24-3 | 角色→模型：`HPSL_ROLE_MODEL_<ROLE>` > `HPSL_DEFAULT_MODEL` > 首个已配密钥厂商 | F8.2「自动分配角色」未实现，先给确定性替代；跳过 Gemini 避免选中占位适配器 |
| D-M24-4 | 无密钥时**先失败再建 session** | 避免"调用没发出去却留下孤立会话" |
| D-M24-5 | `turn` 表本批不写 | INTEGER PK 与 `db.write` 强制 `id` 冲突；留 P0-C |
| D-M24-6 | P0-A 端点只返回 JSON；P0-B 起同端点按 `HX-Request` 返回片段 | 保持既有"双模端点"约定（`projects.py` / `review.py` 同构），页面与 API 共用一条路径 |
| D-M24-7 | 写操作成功后用 `HX-Refresh: true` 整页刷新（建单元 / 备份） | 列表与计数依赖服务端渲染，整页刷新比 OOB 更简单可靠；产出/尝试用局部片段 |
| D-M24-8 | 闭环片段 = `_unit_wf_panel` + `<div id="close-result" hx-swap-oob="true">` | 复用既有面板锚点，同时把"复测入队 N 条"提示打到独立区域 |
| D-M24-9 | 角色面板用 `onchange` 改 `hx-post` 并 `htmx.process()` | 避免为 6 个角色写 6 个表单；无需新增"角色在 body 里"的端点 |
| D-M24-10 | 角色输出用 `html.escape` 后放入 `<pre>` | 模型文本来自外部，必须转义（P1-12 同类问题） |
| D-M24-11 | 设置页改 `fetch` + 手动 `X-CSRF-Token` | `htmx.ajax` 返回 Promise 且不支持 `body` 键，原实现必然失败 |
