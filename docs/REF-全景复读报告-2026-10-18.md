## 2. 架构与代码地图（复读结论）

- **分层**：`app.py`（装配/中间件/CLI）→ `routes/`（66 API + 17 页面）→ `engine/`（headless）→ `db.py`；
  `roles/` 六角色 allow + assembler；`models/` 适配器 + registry；`secrets/` keystore。
- **写纪律**：`db.write` 唯一入口（白名单 14 表，UPDATE/INSERT 禁 REPLACE，同事务 audit）；
  例外仅 `append_audit_event`、`chunk_fts`（检索专用，写锁内单事务）、`delete_source`（同事务手写 audit）。
- **零 DDL 替代存储**：`project.config`（`last_active_at`/`dismissed_prompts`）、`graph_layout.json`、
  `source_index.json`、`HPSL_HOME/secrets/*` —— 这是全程守住 16 对象的关键手法。
- **入口生命周期**（`serve()` 真实顺序）：口令提示 → `atexit(close_all)` → **恢复上次项目** →
  每日快照 → 快照轮转 → 维护线程 → uvicorn；恢复失败降级为空态。
- **启动恢复**：`restore_last_active()` 只读各项目 `config.last_active_at` 取最新，不新增可写状态源；
  `--no-restore` / `HPSL_NO_RESTORE_ACTIVE=1` 可关；顶栏经中间件注入 `active_label`（零额外查库）。
- **错误分层**：`BizError.detail` 承载上游原文；HTMX 分支固定 200 + HTML（`<details>` 折叠），
  REST 仍四字段；但 **REST 用的是注册表文案，自定义 `msg` 被丢弃**（见 §4）。
- **测试**：65 文件 / 567 个 `def test_`；根 conftest 每例隔离 `HPSL_HOME` + 清 `_active_pid`/写连接；
  3 个 skip 全部来自 `test_m33_frontend.py` 的“模板无内联脚本”。

## 3. 仍然成立的关键设计（值得保留）

1. 16 库对象 + 每项目独立库 + WAL + 单写连接 + 5s busy_timeout；审计/撤销可回溯。
2. 六角色 allow 元组 + `answer_machine_output` 永不入 allow + 导入期 assert（A030001）。
3. 八步状态机 + PRODUCE 闸门（空产出必须写理由）+ JUDGE 闭环门控（确认得分/关键卡点/强行闭环理由）。
4. 复测独立于单元状态机，review 保活（result=NULL）只推进 due，结果以 `attempt(kind=复测)` 为准。
5. 成本三态 + 价格表 + `unpriced_models` 显式暴露；取消/撤销/备份/恢复都有 CLI 或 UI 留痕。
6. 安全：口令 + Argon2id + 每文件 16B salt，无口令拒绝而非明文降级；Host/Origin 精确匹配；CSRF 签名。

## 5. 对“594 绿”的正确理解

- 594 例覆盖了**纪律类**（零 DDL/审计/隔离/门控/预算三态计算/CSRF/限流/密钥跨进程）与**主链行为**，质量在同类项目里偏高。
- 但上述 A1–A6 全部**没有测试**：预算“是否拦截”、UI 强关、正常到期复测、`--port` 启动、空态 graph 交互、布局后连线——都是“测试通过但用起来不对”。
- 3 个 skip 只是“模板无内联脚本”，不是失败；`test_m33_frontend` 仅 `node --check` 语法，不执行 DOM。
- 结论：**测试绿灯 ≠ 承诺兑现**；需要补“行为级”用例（预算拦截、CLI 端口、E2E 浏览器、graph 交互）。
