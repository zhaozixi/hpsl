# M40 项目归档 / 删除 + 浏览器 E2E 进套件（2026-10-21）

> 范围：两个待办——「项目归档/删除（`config.archived_at`，零 DDL）」与「浏览器 E2E 进测试套件」。
> 数据层零 DDL：不新增表、不加列、不改 `user_version`。

---

## 1. 归档

### 落地方式

| 项 | 决定 |
|---|---|
| 存储 | `project.config.archived_at`（UTC ISO-8601 字符串）；`null`/缺失 = 未归档 |
| 幂等 | 重复归档**保留原时间戳**，不刷新。历史归档时间被悄悄改写会导致"这个项目什么时候收起来的"无从回答 |
| 当前项目 | 归档 active 项目 → **清空 active 句柄**，回到「未选择项目」空态；不隐式跳到下一个项目（顶栏显示会与用户认知脱节） |
| 启动恢复 | `restore_last_active()` 显式跳过归档项；否则归档了重启还跳回去，等于没归档 |
| REST / CLI | `list_projects()` **默认仍含归档**（`include_archived=True`）。备份、`rotate`、`snapshot` 依赖它——归档若让项目从备份范围消失，等于用"归档"实现了"删除" |
| 页面 | 首页显式 `include_archived=False` 拆成「活跃列表」+「已归档」折叠区 |

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/projects/{pid}/archive` | 归档。HTMX → 面板片段；`origin=detail` → `HX-Redirect: /` |
| POST | `/api/v1/projects/{pid}/unarchive` | 取消归档。`origin=detail` → `HX-Redirect: /projects/{pid}` |

## 2. 删除

### 三个不是随手写的取舍

1. **要求逐字输入项目名**：`confirm_name` 必须与项目名逐字一致，否则 `C400001`。只按 pid 或一次点击就删，误触代价不可逆。
2. **不 `rmtree`，改为整目录 `rename` 到 `HPSL_HOME/trash/`**：同分区 rename 原子完成，误删可从文件系统直接取回。程序不替用户做不可逆操作。回收目录按 `{pid}-{UTC}` 命名，互不覆盖。
3. **先 `db.close_project` 再 rename**：Windows 上 sqlite 占用中的文件 rename 会失败；先释放写连接（含 WAL checkpoint）再动目录。

### 审计口径

`project.db` 随目录一起进 trash，删除前的全部审计记录仍在库内可查。删除动作本身不额外写审计行——库已不在原路径，写进去也没人读得到。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/projects/{pid}/delete` | 表单字段 `confirm_name`（必填）+ `origin`（`list`/`detail`）；返回 `{deleted, name, trash_path}` |

## 3. 页面交互

- 首页抽 `_project_panel.html`：整页渲染与 HTMX 片段共用同一模板，避免两处口径漂移；片段外层保留 `id="project-panel"` 供 `hx-swap="outerHTML"` 定位。
- 活跃行：`[切换到此项目] [归档]`；归档行：`[取消归档]` + 折叠的删除表单。
- **错误必须保留面板**：删除/归档失败时返回「完整面板 + 顶部红条（`.banner.err`）」，而不是只返回一个错误片段。否则 `outerHTML` 会把整个项目列表换成一个 `<p>`，用户得手动刷新才能恢复。
- 详情页操作区：归档/删除后走 `HX-Redirect` 回列表（删除后该 URL 已无意义）。

## 4. 浏览器 E2E 进套件

### 结构

```
tests/e2e/
├── conftest.py                    # live_server + node_playwright 夹具
├── flows/project_lifecycle.js     # Playwright 剧本（node）
└── test_project_lifecycle.py      # pytest 驱动器
```

### 三个关键决定

| 决定 | 原因 |
|---|---|
| **默认关闭**，`HPSL_E2E=1` 开启 | 真起服务 + 真开 Chromium 一次 20+ 秒；塞进默认全量会让 90 秒的套件变成几分钟，且没装浏览器的机器上一片红 |
| 用**环境变量**而非 `--run-e2e` | pytest 8 里子目录 conftest 调 `addoption` 属于晚注册，会直接报错 |
| 服务用**子进程**起，不用同进程线程 | 根 conftest 的 autouse `isolated_home` 每个用例都改本进程 `HPSL_HOME`；同进程 uvicorn 会跟着漂到各个临时目录。子进程拿独立 env，顺带验证了真实的 `python -m hpsl serve` 路径 |

缺 node 或缺 playwright 时自动 `skip`，不制造假红灯。

### 剧本覆盖（15 步）

首页 200 → 新建项目（验证自动切到 `/unit`）→ 出现在活跃列表 → 归档（离开活跃列表 / 出现归档区 / 顶部提示）→ 取消归档（回到活跃列表）→ 再归档 → **错误名称删除**（报错 + 面板仍在）→ **正确名称删除**（列表与归档区都消失 / 提示回收目录）→ 详情页归档自动回列表 → 详情页显示「已归档」徽标 → 收尾清理 → **零 console error** → **375px 无横向溢出**。

## 6. 已知取舍

- **trash 不会自动清理**：故意不做。什么时候算"确实不要了"只有用户知道；自动过期删除会把"可恢复"变成"看运气"。
  M41 补了显式出口：`hpsl trash list` 与 `hpsl trash purge --days 30 --yes`（默认只预览），仍不替用户自动删。
- **归档不影响计费与统计**：归档项目的花费仍计入统计（历史花费不会因归档而变化），只有列表展示与启动恢复受影响。
- **删除后无法在界面里恢复**：只能从 `HPSL_HOME/trash/` 手动搬回（把目录名还原成 pid 即可被重新识别）。界面化"回收站"留作后续。
