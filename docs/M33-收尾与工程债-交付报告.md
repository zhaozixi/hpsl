## 4. `.venv` 重建（含一个反直觉的坑）

### 现象

`venv/Scripts/python.exe` 一律以退出码 103 失败：`did not find executable at '<base>\python.exe'`，
而该 base python **确实存在且可直接运行**。用 anaconda python 作 base 能建成功。

### 真正的问题

能建成的 venv（anaconda base 或 vendor base）在**项目盘（D:）**运行时，SQLite 单条 DDL 耗时
从 0.006s 涨到 0.082s，单个测试文件 2.6s → 19.3s，全量从 ~70s 涨到 5 分钟以上。
交叉对照确认：与解释器版本、`sqlite3.dll` 哈希、journal/synchronous 设置、`.pth` 钩子、base 路径**都无关**，
只与「venv 的 exe 落在 D 盘」相关；同一份文件放 C 盘即恢复。

### 采用的方案

```powershell
python -m venv C:\Users\<user>\.workbuddy\binaries\python\envs\hpsl
# 依赖从既有 site-packages 复用（本机无外网，pip 直连超时）
New-Item -ItemType Junction -Path .venv -Target C:\Users\<user>\.workbuddy\binaries\python\envs\hpsl
```

- `.venv/Scripts/python.exe` 照常可用，`sys.prefix` 显示项目路径；
- 全量回归 **576 passed / 78.44s**（与旧环境 67s 同量级）；
- base 解释器复制在 `...\binaries\python\bases\3.13.14`，与 venv 同盘（C）。

> 局限：`.venv` 依赖 C 盘的 `binaries\python\envs\hpsl`。若该目录被清理，`.venv` 需重建
>（README 已写明重建方法）。
