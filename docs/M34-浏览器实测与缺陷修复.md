## 三、缺陷与修复

### D-01【致命】服务重启后，用户无法在界面上回到任何已有项目

- **现象**：`_active_pid` 是进程内句柄（`projects.py` 文档声明的设计），重启即清空。
  清空后 `/unit` 等页全部提示「尚未选择项目」。而**全站只有向导第 1 步会调 `switch`**，
  且该步在「同名项目已存在」时直接 `return`，根本走不到 `switch`。
  → 重启一次，项目彻底失联，只能重启进程或手搓 API。
- **根因**：`switch` API 一直存在，但**从未有 UI 入口**。
- **修复**：
  - 首页项目列表每项增加「切换到此项目」按钮，当前项目标「当前」徽标；
  - 项目详情页增加「切换到此项目」/「当前使用中 · 进入学习 →」；
  - `app.js` 新增 `hpslSwitchProject()`（读 `hpsl_csrf` cookie → `POST .../switch` → 跳 `/unit`），
    并复用已有 toast 呈现失败。
- **涉及**：`routes/projects.py`、`templates/index.html`、`templates/project_detail.html`、`static/app.js`
- **复验**：首页点击 → `200` → 落 `/unit`，标题「单元 · 学会 SQL 查询优化」✅

### D-02【严重】HTMX 表单报错时把裸 JSON 塞进页面；面板类操作直接丢锚点

- **现象**：业务错误按项目约定返回 `HTTP 200 + {code,msg}`。HTMX 见 2xx 即 swap：
  - `#production-result` / `#attempt-result` / `#create-result` 等 innerHTML 目标 → 显示一坨 `{"code":...}`；
  - `#wf-panel`（`hx-swap="outerHTML"`）→ **整个工作流面板被 JSON 顶掉**，后续按钮全消失，功能中断。
- **修复**：
  - 全局 `BizError` handler 分流：带 `HX-Request` 头时返回人读 HTML 片段
    （`<p class="result err">文案（错误码）</p>`），**状态码固定 200**——HTMX 默认只 swap 2xx，
    沿用 4xx 会让错误被静默丢弃；
  - 两个 `outerHTML` 端点（`move` / `close`）单独兜底：`_wf_panel_error()` 按库中真实状态
    重建 `#wf-panel` 并附错误文案，锚点不丢。
- **涉及**：`app.py`、`routes/unit.py`、`templates/_unit_wf_panel.html`
- **复验**：「产出中」直接点「推进到验证中」→ 面板留存、顶部显示
  「跳过产出需要写一句理由」、**无裸 JSON**、按钮仍可用 ✅

### D-03【严重】闭环 UI 与状态脱节，推进到「评判中」后反而无法闭环

- **现象**：①判定闭环区在非 JUDGE 状态仍可点，点了才报错；
  改为条件渲染后更糟——状态推进走局部替换，⑤ 区不重绘，
  推进到 JUDGE 后表单**永远不出现**，单元被彻底堵死。
- **修复**：
  - 抽出 `_unit_close_panel.html`，整页 `include` + 状态推进时以 `hx-swap-oob` 替换；
  - 表单**常驻**（保持页面结构稳定），仅 JUDGE 可操作（`disabled`）；
  - 文案分档：JUDGE 前提示「请先推进到评判中」，`INTEGRATE/CLOSED` 提示「已闭环，无需再次判定」。
  - `move` 与 `close` 成功分支都追加该 OOB；`close` 内顺序须「先整体替换闭环区、再塞结果提示」，
    否则提示会被随后替换的空白 `#close-result` 清掉。
- **涉及**：`templates/_unit_close_panel.html`（新增）、`templates/unit_detail.html`、`routes/unit.py`
- **复验**：全程推进时闭环表单 `disabled`；JUDGE 时解禁；闭环后恢复 `disabled`
  且保留「已闭环；本单元尚未关联概念，暂无复测。」✅

### D-04【体验】概念图空态抛 JS 异常

- **现象**：`/graph` 无节点时 `PAGEERROR: Cannot read properties of null (reading 'addEventListener')`。
  模板用 `{% if nodes %}` 跳过 `<svg>`，但脚本无条件执行 `svg.addEventListener`。
- **修复**：空态仍输出隐藏锚点（`<svg id="concept-graph" style="display:none">` + `#viewport` + `#graph-tooltip`）。
  （未采用「把脚本包进 `if`」：脚本里 `zoomBy/resetView/...` 被大量内联 `onclick` 引用，必须保持全局。）
- **复验**：空态 `0` 错误，提示文案与视觉不变 ✅

### D-05【体验】向导第 1 步成功后，顶部横幅仍写「尚未选择项目」

- **现象**：`stepCreate()` 只更新 `#r-1`，服务端渲染的 `active` 横幅不刷新 → 同屏自相矛盾。
- **修复**：横幅加 `id="active-banner"`，创建切换成功后用 DOM API（`textContent`，非 innerHTML）就地改写。
- **复验**：`class` 由 `banner warn` → `banner ok`，文案同步 ✅

### D-06【体验】向导第 2 步把技术字段直接给用户看

- **现象**：`已保存；has_key=true，尾号 abcd，存储=fernet_file`
- **修复**：改为
  `已保存 DeepSeek（深度求索）的密钥：尾号 abcd，存放在本地加密文件。`
  （`keyring` → 系统钥匙串 / `fernet_file` → 本地加密文件 / 其他 → 未知位置）
- **复验**：全中文，无字段名 ✅

### D-07【体验】宏尾换行被渲染成空格：「推进到「选题中 」」

- **根因**：`state_name` / `actor_label` / `table_label` / `source_kind_label` / `role_label`
  五个宏的 `{{ m.get(...) }}` 后紧跟换行，`{% endmacro %}` 未做空白控制 → 输出尾随 `\n`。
  在表格里无害，但紧贴标点就露馅。
- **修复**：统一改 `{{- ... -}}`。
- **复验**：按钮文本精确等于 `推进到「选题中」` ✅

### D-08【体验】单元元信息残留机器值

- **现象**：`是否跳过产出：1`、`是否强制闭环：0`、`闭环时间：2026-10-18T07:39:52.835Z`（UTC）
- **修复**：布尔改 `bool_badge`（已跳过 / 否）；页面层把 `produced_at/closed_at/created_at`
  转本地时间 `YYYY-MM-DD HH:MM`（**REST API 仍返回原始 ISO**，便于程序处理）。
- **复验**：`是否跳过产出：已跳过`、`闭环时间：2026-10-18 15:39`（UTC+8 正确）✅

## 四、发现但**未改**的观察项

| 项 | 说明 | 处置 |
|---|---|---|
| `_active_pid` 重启丢失 | 文档声明的进程内设计，未擅自改为持久化 | 已用 D-01 的切换入口缓解；是否持久化待决策 |
