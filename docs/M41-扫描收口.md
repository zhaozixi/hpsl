## 2. 三个取舍写清楚

1. **归档 ≠ 可切换**：归档语义是「收起来」。继续让它当 active，顶栏「当前项目」会指向一个用户以为已经收起来的项目，后续操作对象全部错位。页面隐藏按钮不算防线——API 是公开的。
2. **逐字就是逐字**：`strip()` 是「宽容输入」的惯性写法，但删除确认的唯一价值就在**不宽容**。改严格后尾随空格直接 `C400001`，代价是用户多按一次退格，收益是误删概率下降。
3. **金额位数随量级变**：人民币折算后极小值固定 4 位会显示 `¥0.0000`——等于告诉用户「这次没花钱」，与记账的目的相反。六位下限是「宁可难看，不可失真」。

## 3. 回收站 CLI

| 命令 | 行为 |
|---|---|
| `hpsl trash list` | 列出 `HPSL_HOME/trash/` 下每个目录名与本地时间；空则 `[trash] empty` |
| `hpsl trash purge --days 30` | **只预览**：列出候选目录与数量，末行提示「未删除；确认后加 --yes」 |
| `hpsl trash purge --days 30 --yes` | 真删，回报删除个数；`--days` 负数 → 参数错误 |

设计延续 M40 的「不替用户做不可逆操作」：默认只预览，真删必须显式 `--yes`。
程序仍**不自动清理**——多久算「真不要了」只有用户知道，定时删是把判断权从人手里拿走。

## 6. REF-5 追加收口（同日二轮扫描）

REF-5 复扫时发现打包自检**不可重入**，本批一并修掉：

| 问题 | 根因 | 修法 |
|---|---|---|
| `scripts/check_package.py` 第二次运行必失败：`WinError 183: build\bdist.win-amd64\wheel\hpsl-0.1.0.dist-info 已存在` | `finally` 里 `shutil.rmtree(build, ignore_errors=True)` 在 Windows 上因子进程句柄未释放而**静默失败**，`build/` 残留，下次构建无法重建 `dist-info` | 新增 `_purge_build_dir()`：构建**前**清一次（兼容历史残留）、构建**后**再清一次；清理失败重试 3 轮，仍失败则 `stderr` 明确告警（不再静默） |
| 构建失败时错误输出可能为空 | `subprocess.run(text=True)` 按 GBK 解码 pip 输出，遇非 GBK 字节抛 `UnicodeDecodeError`（与 F-01 同源） | 两处 `subprocess.run` 统一 `encoding="utf-8", errors="replace"` |

验收：手动植入 `build/bdist.win-amd64/wheel/hpsl-0.1.0.dist-info` 残留后，连续两次运行均 `PASS`（108 条目 / 模板 29 / 提示词 6 / 静态 5），结束后 `build/` 零残留。
