> 文档类型：需求基线

---

## 1. 背景

M24 让角色调用能真实调用模型并记账，但 `turn` 表仍为空：调用过程不可回放，`session` 只是记账外键的载体。本里程碑把「一轮对话」持久化，并在单元详情提供回放。

---

## 2. 范围

| # | 能力 | 落点 |
|---|---|---|
| 1 | `db.write` 支持 `turn`（INTEGER PK）省略 id | `hpsl/db.py` |
| 2 | 追加一轮对话（同事务审计） | `db.append_turn(...)` |
| 3 | 按单元/会话读取轮次 | `db.list_turns(...)` |
| 4 | 角色调用写两轮（user 输入 + 角色输出） | `engine/role_llm.call_role` |
| 5 | 单元详情「⑨ 会话记录」+ REST `turns` | `routes/unit.py`、`unit_detail.html` |

**Out-of-Scope**：流式分片落库、对话删除/编辑、对话导出（Markdown 导出暂不含 turn）、分页与搜索。

---

## 3. 契约

### 3.1 写入

```python
db.append_turn(pid, session_id, role, content, *, provider=None, model=None, actor="system") -> str
```

- `turn` 为追加表：`id` 由 SQLite 生成；`write()` 对**仅 `turn`** 允许省略 `id`，其余表仍强制。
- 与业务写入相同：`BEGIN IMMEDIATE` + 同事务 `audit_log`；返回自增 id 字符串。
- 角色调用固定写两行：`role="user"`（actor=user）→ `role=<角色名>`（actor=system，带 provider/model）。

### 3.2 读取

```python
db.list_turns(pid, *, unit_id=None, session_id=None, limit=200) -> list[dict]
```

- 均按 `id ASC`（=时间序）；`unit_id` 走 `turn JOIN session`。

### 3.3 页面 / REST

- `GET /unit/{uid}`：新增「⑨ 会话记录」，按角色中文名展示（我 / 答案机 / 提问者 / 出题者 / 挑错者 / 书记员 / 选题助手），输出用 `<pre>` 转义。
- `GET /api/v1/units/{uid}`：新增 `turns` 数组。
- 角色调用 HTMX 片段末尾提供「刷新页面查看完整会话记录」链接。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| `turn` 自增依赖 SQLite `lastrowid` | 单写连接 + 每 pid 锁串行，无并发竞争 |
| 对话内容可能含敏感信息 | 仅存本地库；日志不写正文（既有红线）；导出暂不含 turn |
| 长对话拖慢详情页 | `LIMIT 100`；后续可加分页 |
