## 2. 范围与边界

### 2.1 In-Scope 已交付
1. **`compute_counts(pid) -> CountsVO`**：只读聚合重算 12 项四平面计数指标（强行闭环剔除 / 复测加权 / 零缺口分母限定 / 孤岛·分歧读 concept_edge·claim_check）。
2. **`counts_context(pid) -> dict`**：样本基数（attempts / calibration_samples / confirmed_sessions / total_units / total_concepts / total_gaps），供软提示守卫。
3. **`plane_signals(counts, cfg, *, ctx, max_prompts) -> list[SoftPromptVO]`**：四平面阈值比对生成软提示；优先级 风险 > 质量 > 节奏 > 进度；全部 `dismissible=True`；上限可配；样本不足不误报。
4. **DTO/VO（`common/dto.py`）**：`CountsVO`（frozen, 12 字段）、`SoftPromptVO`（id/plane/level/message/dismissible）。
5. **导出补齐**：`engine/__init__.py` 导出 `compute_counts` / `counts_context` / `plane_signals`。
6. **测试**：`tests/test_governance.py`（17 例，覆盖空项目全零、样本不足无误导、pass_rate 剔除+加权、calibration_gap、zero_gap 分母、l1_gap_sessions、单元比率、gap 清账+积压、孤岛占比、未裁决分歧排除同源、四平面阈值触发与优先级、max_prompts 截断、counts_context 基数、无 pid 回退激活、零 DDL）。

### 2.2 Out-of-Scope（留待后续，未做）
- HTTP 路由（`/api/v1/counts`、`/api/v1/counts/planes`、`/api/v1/soft-prompts`、`/api/v1/soft-prompts/{id}/dismiss`）属 **M10**；`SoftPromptVO` 即 M10 响应载体。
- `suggest_band(stats, cfg)`（难度升降建议）属 **v1（O3，本期待留）**——M9 仅输出软提示，不裁决升降。
- 账本总览四平面视图 / 超限确认弹层 / 备份导出 / 卡片与概念图 UI 属 **M10**。
- M10 展示层须对「分母为 0」指标标注「数据积累中」（M9 已在指标层返回 0.0，提示层经 ctx 守卫避免误报）。

## 3. 与锁定基线的偏差与实现决策（须记录）

| # | 偏差/决策 | 原因 | 处理 | 影响 |
|---|-----------|------|------|------|
| D-M9-1 | 内部 API 收 `project_id`，无参回退 `projects.active_project()` | §3.2.M9.2 字面签名；与 M8「激活项目上下文」对齐 | 未激活 → `ValueError`（不新增业务码，严守 M9 无新码空间） | 严格对齐锁定基线 |
| D-M9-2 | 新增 `counts_context(pid)` 暴露样本基数 | `plane_signals` 需「无数据不误报」守卫，CountsVO 固定 12 字段不可扩容 | 独立只读函数，与 `compute_counts` 共享 `_aggregate` | 签名友好，零 DDL |
| D-M9-3 | `zero_gap_ratio` 按「会话归属单元零缺口」判定 | M7 候选确认 gap 的 `session_id` 为 NULL，逐会话计数失真 | 文档标注；单元级零缺口更稳 | 口径与 §3.2.M9.5「分母只算已确认会话」精神一致 |
| D-M9-4 | `unresolved_disagreements` 排除 `providers.same_source=True` | 同源降级告警非实质分歧（仅 BD-03 闭环门控用） | Python 端解析 providers JSON 过滤 | 计数准确 |

> 以上偏差均不破坏 M0 锁定的 16 库对象（零 DDL 已实测验证）。
