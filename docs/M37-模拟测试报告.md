## 发现并修复

### M37-F01 无密钥文案仍在讲 Gemini（已修）

角色调用触发：

```
没有可用的模型密钥：请先在设置页填写任一厂商的 API 密钥（Gemini 当前为占位实现，暂不参与自动选择）（A040003）
```

M33 已把厂商收敛为国内三家，`models.yaml` 里没有 Gemini，向导与设置页也不会出现它。这句括号注释是收敛前留下的，用户读到只会困惑「Gemini 是什么，我要去哪找」。`pick_default_model` 里那句 `if provider_kind == "gemini": continue` 同理是死防御（保留无害，文档已说明「重新启用只需改 YAML」）。

### M37-F02 文案指向一个不存在的位置（已修，问题比 F01 严重）

同一句还写着「请先在**设置页**填写」，401 分支写着「请到**设置 → 密钥**重新填写」。实际上：

- `settings.html` 里没有任何密钥区块（`git log -S` 追溯：该页面从未有过）；
- 全站唯一能填密钥的地方是 `/wizard` 第 2 步；
- 导航里也没有「密钥」入口，`help.html` 也只教走去导第 2 步。

也就是说，用户被指向一个做不到这件事的页面。修复为统一指向「向导 → 第 2 步」，涉及三处：

| 位置 | 场景 |
|---|---|
| `hpsl/models/registry.py` `pick_default_model` | 完全没有可用密钥（最常见） |
| `hpsl/models/openai_compat.py` `_HTTP_HINTS[401]` | 密钥失效（真实上游 401） |
| `hpsl/models/anthropic.py` `_build_headers` | 密钥缺失（适配器保留分支） |

修复后浏览器实测：

```
role-result: 没有可用的模型密钥：请到「向导 → 第 2 步」填写 DeepSeek / 千问 / 智谱 任一家的 API 密钥（A040003）
wizard r-3: 连接未通过：密钥缺失或无效（A040003）
```

全量测试 `692 passed, 3 skipped`。

## 未修（需你决策）

**密钥只能从向导进，没有独立入口。** 修 F02 只是让文案不再撒谎；产品层面「换一把密钥」仍要求用户重走向导第 2 步（哪怕第 1 步已经完成）。补一个「设置 → 密钥」区块是功能开发，涉及厂商下拉、保存/测试、掩码回显、CSRF，不在本轮测试范围内，未动。

**预算闸门未能实测。** `A080001` 需要「已有密钥且超预算」才触发；本轮 tmp-live 无任何密钥，调用在 `pick_default_model` 就返回 A040003，永远走不到 `ensure_budget`。这不算闸门失效，只是本轮无法证明它生效——单测侧有覆盖，浏览器侧尚无。

## 首轮脚本的三处误判（记录以正视听）

第一轮脚本报 FAIL 的三项，复核后都是脚本自己的判据错，产品无问题：

| 误判 | 真实情况 |
|---|---|
| 主题 `data-theme` 由 null→null | 实现用的是 `html.dark` class，不是 `data-theme`；改判 `classList` 后 PASS |
| 三问「未就地生效」 | 设计就是 toast 后刷新，`window` 标记丢失是刷新导致；改为断言 toast + 回显后 PASS |
| 向导「无提示」 | 结果容器是 `#r-3`，脚本找的 `#test-result`；改选择器后 PASS |
