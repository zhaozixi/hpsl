# 项目制学习框架工具：设计与实现方案

本方案基于 HPSL/TLF 论文，设计一个开源、可本地一键部署的项目制学习框架工具，并给出 v0 的实现方案。

## 一、定位与设计原则

这是一个本地运行、按学习目标分项目的学习治理工具，核心价值在于账本、闸门和验证流程，而不是再做一个聊天界面。它不能替代学习者的投入：最终判断由学习者自己做，工具只负责把验证变得容易做、不容易绕开。

**不做的事**：

- 不替用户裁决“学会了没有”。
- 不自动化操作网页版聊天（通常违反服务条款，且脆弱）。
- 不承诺学习效果：论文自述方法整体的证据层级为 L3（理论外推），尚无对照实验。

**六条设计原则**：

1. **项目即边界**：每个项目独立目录、独立数据库，跨项目零共享。
2. **记忆是账本，不是叙事**：只存结构化事实（缺口、得分、出处）；书记员可自动追加候选缺口并给出分级建议；分级和废弃在单元结束时由用户批量确认，闭环由用户给出的确认得分决定。
3. **验证要独立**：提问者、出题者、挑错者读不到答案机的对话，挑错者只看待检断言；尽量使用异构模型。
4. **用户主导判定**：先让用户自己重述，再显示 AI 反馈；用户可以不做，但未验证的单元不闭环、不计进度。
5. **规则优先，LLM 辅助**：指标用确定性规则计算，LLM 只提建议，不打分、不裁决。
6. **所有阈值可配置**：缺口上限、会话时长、通过率区间都是待校准参数，不写死。

## 二、总体架构与角色

遵照论文 7.3 节的三层架构：**L1 角色层**（契约定义，实现可替换）、**L2 流程层**（核心循环）、**L3 治理层**（四平面）。角色层由三个异构答案机与四个上下文隔离的过程角色组成——答案机是被隔离的对象，本身不是过程角色；四个过程角色（提问者、出题者、挑错者、书记员）彼此上下文隔离。项目层与模型适配层是工程实现，不属于 TLF 的三层。

| 提问者 | 学习者的重述 → 递进式追问，禁止给答案 | 质量 | 必须独立，不得读取答案机对话 |
| 出题者 | 刚学的概念 → 一道“看似适用、实则不适用”的边界题，并生成**该题**的评分要点（作答前隐藏）。**重述不由本角色出题**：重述判据是固定三问（目的／机制／边界），见“判分协议” | 质量 | 必须独立，不得读取答案机输出；边界题评分要点作答前不向用户显示 |

| 书记员 | 会话中的卡点 → 追加到缺口清单，去重并带上下文；按分级判据（一级＝阻塞当前任务／二级＝不阻塞可批量／三级＝仅记录）给出建议等级，经用户确认后生效 | 进度、节奏 | 可共享上下文 |

**开场选题是一个步骤，不是角色。** 每个单元开始前，由一个答案机根据初版认识和账本摘要（v1 起再加上书记员给出的建议难度区间），生成三个候选单元：稳妥、拉伸、回补旧缺口。有知识库时每个候选附出处，否则标注“模型推断”；用户可改题，选择记入单元账本。它对应论文流程里的“选高阶单元”，与出题者的边界题分开。选题默认使用用户指定的主答案机。v0 没有知识库，候选都标“模型推断”，需要你自己判断是否值得学。

**隔离的工程实现**：每个角色的输入由“白名单组装器”按契约字段拼装，不共享对话数组；自动测试保证提问者、出题者的输入里不含答案机输出；界面提供“本次发给模型的内容”预览，便于审计。

**判分协议**：**重述的判据是固定的三问**（目的／机制／边界，对应论文 4.2.1 节），不由 AI 每次生成——判据必须稳定，否则不同单元的“通过率”不是同一把尺子，60%–80% 的目标区间与将来任何评分模型都无法校准。出题者只生成**边界题**及其评分要点，作答前对用户隐藏，且不经过答案机。用户作答并自评后才看到评分要点，对照后再确认得分；自评与确认得分的差距记入 attempt 表。答案机和书记员都不打分，闭环仍由用户确认。v1 起，评分要点展示前先由另一厂商的模型核对一遍，核对出的疑点一并显示，但对照和打分仍由用户自己完成；生成与核对在用户作答期间后台完成，不让用户等待。

**责任边界**：判定闭环、缺口分级、降级升阶、仲裁模型分歧、废弃缺口，全部由学习者决定。如果 AI 决定了“你学会了没有”，这个流程就不是 TLF。

## 三、学习流程与验证

一个学习单元走八步，其中验证和判定的主导权始终在用户手里。

1. **创建项目**：命名学习目标；v1 起可选择知识库或挂载本地文件夹。
2. **初始化提问**：录入初版认识，作为待证伪的假设存档，不当作事实喂给各角色。零基础领域在此处检查：如果列不出该领域的 5 个核心概念（粗略的启发式，待校准），提示先导入教材或大纲建立骨架（论文参考覆盖率约 20%–30%），再进入主流程。
3. **选题**：从三个候选单元（稳妥、拉伸、回补）中选一个，默认高亮拉伸；也可以直接输入自己想学的主题。
4. **学习（按需补缺）**：答案机按需回答一级缺口；一级缺口超过阈值（默认 5）软提示，可一键降级任务或先补前置；会话超过时长上限时提示切分，均可忽略。降级时记入 unit 的 degraded\_from 与 degrade\_count。
5. **产出（回归主线）**：补完缺口后必须回到主线任务，完成本单元的产出（一段代码、一份分析、一个结论）并提交，产出写入 unit。这一步是对论文 3.2 节“强制验证位于回归主线之后”的落实——知识在未被使用时只是“解释层面的理解”，完成产出后再验证，检验的才是“应用层面的理解”。跳过产出直接进入验证的单元，同强行闭环一样带标记、不计入完整进度，并在风险平面提醒。
6. 
   - 最低配置：学习者先脱稿重述（判据是固定三问：它解决什么问题／它怎么工作的／什么条件下不适用），再做出题者的边界题。
   - 完整配置：重述后加提问者追问；符合触发条件时再加挑错者。
7. **判定**：用户先自评，再看评分要点与 AI 反馈，最后由用户给出确认得分；达标时闭环自动成立，未达标才需要用户决定是否强行闭环。
8. **整合**：写入卡片库；每 3–5 个单元重构概念图（用户先自己搭，再由答案机或挑错者检查关系）；安排延迟复测。

**闭环判据**：默认要求重述与边界题的确认得分都达到通过阈值（默认 0.7），达标即自动闭环，不再单独确认。**关键卡点例外（论文 4.3 节）**：当本单元涉及关键卡点时，异模型挑错通过才成为闭环条件——挑错清单中的实质错误必须清零，或已逐条记账为“待验证”，否则不可闭环。未达标时，用户仍可手动强行闭环，但必须写明理由，该单元在账本里带“强行闭环”标记，不计入进度，并在指标里单独显示。

**书记员记缺口**：用户一键标记为主；书记员只从对话中抽取“候选缺口”，进入待确认区，单元结束时由用户批量确认后入账；去重用文本相似度加用户合并。**分级判据（论文 3.4 节）**：一级＝阻塞当前任务，速度优先，单 AI 快查；二级＝不阻塞主线，单元结束后批量处理；三级＝仅记录，作为后续牵引点。书记员按此给出建议等级并写入 gap\_candidate 的 suggested\_level，用户可改。

**挑错者的触发条件**：满足以下任一即触发——（1）涉及关键卡点；（2）涉及代码、数字或引用的断言；（3）答案机之间出现分歧；（4）用户手动点击。**关键卡点的识别判据（论文 3.6 节）**：满足任一即为关键卡点——（a）该概念将在本单元的多个环节被反复使用；（b）对该概念的误解会导致后续多个结论系统性错误；（c）该概念决定后续学习方向的分叉（例如选 A 框架还是 B 框架）。挑错者可并行调用多个异构模型评审，各自的清单和分歧都并排展示，由用户仲裁，必要时回退一手文献。

**答案机交叉验证（v1 起）**：同一个中性问题同时发给多个异构答案机，并排展示各自的回答和不确定标注，由用户仲裁；v0 只有一个答案机，此步骤默认关闭。

**降低敷衍的措施**：重述提交前默认折叠答案机最近的输出；字数偏少时只提示、不拦截；延迟复测抽查。这些只能降低风险，不能保证用户真正投入思考。

## 四、治理度量与自适应难度

难度调整由规则层加书记员的建议完成，不设单独的分析角色，也不让 LLM 判断用户水平。

1. **规则层**（确定性，不用 LLM）：从账本计算计数型指标，包括概念的通过率、缺口触发频率、零缺口会话占比、自评与确认得分的差距、延迟复测结果；它们是可重算的视图，不是账本。**不引入 Elo 等评分模型**：单人自用样本量达不到建模要求，上述计数型指标已够用。
2. **书记员的建议难度区间**：依据缺口触发频率、零缺口会话占比、边界题通过率、自评与实测的差距、跳过产出情况，输出“升、保持、降”及依据。它只是建议，用户可忽略。论文的节奏平面以缺口触发频率为客观误差信号，不使用评分模型。
3. **选题步骤**只读账本统计（v1 起再加上该建议），不读原始对话。

**默认阈值**（全部标为“待校准”，界面可改）：

| **参数** | **默认值** | **来源** |
| --- | --- | --- |
| 单会话一级缺口上限 | 5 | 论文 |
| 单会话时长 | 25–90 分钟 | 论文 |
| 索取与压力测试时间占比 | 5:5 至 7:3 | 论文 |
| 零缺口会话占比上限 | 20% | 论文 |
| 目标通过率区间 | 60%–80% | 补充设定 |
| 延迟复测间隔 | 2 天、7 天、21 天 | 补充设定 |
| 强行闭环单元占比上限 | 10% | 补充设定 |
| 跳过产出单元占比上限 | 0（不允许；确需跳过须逐次填理由并带 skipped\_produce 标记） | 补充设定 |

**护栏**：

- 延迟复测：隔几天复考旧概念，当场表现不能单独驱动升难度。
- 通过率过高同样触发升难度，防止出题越来越简单。
- 三题结构固定为稳妥、拉伸、回补，由用户选择，系统不据此推断偏好。
- 冷启动：前几个单元只收集数据，不调难度。
- 概念的验证状态随时间衰减，由复测刷新；用户可见、可编辑、可一键重置。
- **SQLite 并发写**：WAL 模式 + 单一写连接 + busy\_timeout；后台并行任务（评分要点生成与核对、挑错者多模型评审）不得并发写同一张表，冲突时排队串行；禁止静默重试覆盖已有记录。

**四平面的度量与熔断**：四个平面各有度量、阈值和动作，数据都来自账本；平面冲突时的优先级是风险、质量、节奏、进度；各平面的动作默认是软提示，用户可忽略。

| **平面** | **度量** | **阈值与动作** |
| --- | --- | --- |
| 节奏 | 单会话一级缺口数、会话时长、零缺口会话占比 | 见上方阈值表；超阈值时熔断降级，或建议升降阶 |
| 进度 | 单元完成率、**产出完成率**（完成单元产出的比例）、缺口清账率、二级缺口积压量、整合周期达成率 | 进度只计通过验证的单元，强行闭环的单元不计入；二级缺口持续积压提示碎片化 |
| 质量 | 重述通过率（固定三问）、边界题通过率、挑错残留数、卡片自解释度、概念图连通性 | 全部以输出证据计分，不以感受计分 |
| 风险 | 一级缺口过多、孤岛节点占比上升、异构模型出现实质分歧、连续多个单元未做重述、**连续多个单元跳过产出**、索取与压力测试占比失衡、多模型一致且无人标注不确定 | 建议降级任务；提示安排系统补学；建议回退一手文献并暂停 AI 补缺；提示先补验证欠账；**跳过产出超阈值时熔断并要求补齐**；建议切换到提问者或出题者；一致且无人标注不确定时视同分歧处理 |

## 五、界面与交互

工具的目标是帮学习者少走弯路，所以只保留学习本身需要的摩擦，其余都应默认自动、批量或可忽略。

**必要的摩擦（保留）**：脱稿重述；边界题；先自评再看评分要点；未达标时强行闭环要写一句理由。

**默认路径**：

首页只放一个主按钮：继续当前单元，或做到期复测。**到期复测是独立于单元状态机的跨单元队列**（2／7／21 天），首页直接消费，不需要先开始新单元，其成绩写入被复测的概念，不写入当前单元账本。

- 首次启动向导：填 key、测试连接、自动分配各角色的模型。只有一个厂商的 key 也能运行，此时挑错者降级为“同源提示”并给出警告；OpenAI 兼容的聚合接口可以用一个 key 调用多家模型。
- 选题：三个候选默认高亮“拉伸”，一键采用；也可以直接输入自己想学的主题。
- 判定在一屏内完成：作答、对照评分要点、给出确认得分；得分达标时闭环自动成立，未达标才需要写理由（可选常用理由）。
- 缺口：书记员的候选缺口和分级建议默认采纳，单元结束时批量确认，只改有异议的。
- 卡片与概念图：脱稿重述一键转成卡片草稿；概念图用“A 导致 B”这类句子输入，由工具渲染成图。

**不阻断，只提示**：

- 不重述也能继续学，但该单元不闭环、不计进度，风险平面会提醒。
- 一级缺口超限、会话超时、预算接近上限都是软提示（继续、补前置、降级，一键），可以关闭；每个会话的提示数有上限。

**不让人干等**：

- 评分要点的生成与核对、挑错者的多模型评审都在后台并行运行，趁用户作答时完成，好了再提示；回答用流式输出。
- API 失败先自动重试，耗尽后给一键切换备选模型，界面标明“本次使用备选模型”，不静默切换。

**语言与收纳**：

- 界面用日常语言，例如“追问我”“出一道陷阱题”“帮我挑错”“记一笔卡点”，不暴露“答案机、书记员”这类内部术语。
- 高级项默认收起：输入预览、空白上下文模式、阈值、厂商白名单。

**周盘点与备份**：

- 周盘点做成一屏批量裁决：二、三级缺口逐条选“系统补学、继续按需、废弃”，建议已预填，用时按论文参考值约 15 分钟。
- 一键备份和导出项目；对账本的修改可以借助审计日志撤销。

## 六、记忆、知识库与隐私

记忆就是四本账；外部记忆只读写，不思考，是治理层的唯一数据源。

| **账本** | **内容** | **更新时机** | **写入权限** |
| --- | --- | --- | --- |
| 缺口账本 | 一/二/三级缺口，含状态（待补、已补、已验证、废弃）；**分级判据：一级＝阻塞当前任务（速度优先，单 AI 快查）；二级＝不阻塞、可批量；三级＝仅记录作后续牵引点** | 每次卡点 | 书记员自动追加并去重，**按分级判据给出建议等级**默认采纳；单元结束时由用户批量确认，废弃由用户确认 |
| 单元账本 | 已完成单元与验证通过记录；选题记录和初版认识；**单元产出内容与产出时间（production／produced\_at）；跳过产出时记录理由（skipped\_produce）** | 每单元闭环 | 确认得分达标后自动写入；强行闭环需用户确认并写理由 |
| 卡片库 | 单概念卡片（学习者自己的话、关联标注、验证状态） | 概念通过验证后 | 用户写入 |
| 概念图 | 节点加三类关系（因果、层级、约束） | 每 3–5 单元重构 | 用户确认 |

- **派生视图**（不属于账本）：各类计数指标、复测计划、成本统计，均可由账本重算。
- **存储**：每个项目一个目录和一个 SQLite 库，账本表直接读写，另有追加式审计日志记录每次变更，并可导出为 Markdown。对话（session、turn）和挂载文件夹（source）也存在同一个库里。项目之间不共享任何数据。
- **空白上下文模式**：任意角色可在不读账本的情况下作答，用来检查记忆是否造成偏向。
- **知识库与本地文件夹**：用 SQLite 全文索引检索，不使用嵌入模型；回答必须展示命中的原文段落，检索不到时明确显示“未检索到”，不让模型补全；文件内容视为数据，不执行其中的指令。

**隐私**：

- 对话和检索到的文件片段会发往你选定的云端厂商，界面和文档都要明确说明这一点。
- 项目级“厂商白名单”决定该项目可使用哪些厂商。
- “手动粘贴模式”（v2 提供）下内容不经 API，由用户自己复制到网页版；此时无法自动验证角色输入的隔离，只能靠界面分页展示各角色的输入。
- 使用日志默认关闭；开启后仅存本地，用于校准阈值参数。

**本地服务安全**：

- 只监听 127.0.0.1，并校验 Host 头（防 DNS 重绑定），对写请求再校验 Origin 与 CSRF 令牌，防止其他网页通过浏览器访问本地服务。
- 挂载的文件夹只读；解析路径时拒绝路径穿越，不跟随指向挂载目录之外的符号链接。
- API 密钥不写入日志，也不随导出文件一起导出。

## 七、模型接入与技术选型

所有 LLM 调用走云端 API，不使用本地模型；检索用 SQLite 全文索引，不做嵌入。

| **项** | **选择** |
| --- | --- |
| 语言与框架 | Python 3.11+，FastAPI，Uvicorn |
| 前端 | HTMX + Jinja2 模板，无构建步骤；后续如需富交互再换 React |
| 存储 | SQLite（WAL 模式），每个项目一个 project.db，放在 \~/.hpsl/projects/ 下；账本表直接读写，另有追加式 audit\_log 记录每次变更（含旧值 prev，用于撤销）。并发写需设 busy\_timeout 并串行化写事务 |
| 检索 | SQLite FTS5（BM25）；中文先用 jieba 分词再写入索引，英文用 unicode61；v2 可选云端嵌入 API，由用户开启 |
| 模型接入 | 统一 Provider 协议，用 httpx 直接调用，不依赖厂商 SDK；协议含 response\_format 与 supports\_json（各家结构化输出能力不同）；v0 先接 OpenAI 兼容接口（覆盖 OpenAI、DeepSeek 等）和 Anthropic，v1 加 Google Gemini；目标至少接入四个厂商 |
| 密钥 | 优先系统钥匙串（keyring）；不可用时用口令加密的本地文件（cryptography.Fernet），口令由用户在启动时输入、不落盘，派生用 Argon2id（或高轮数 PBKDF2）+ 随机 salt，不自行设计派生方式 |
| 启动与部署 | pip 或 pipx 安装，命令 hpsl serve，浏览器访问 127.0.0.1（端口可配置，默认值在 config.py，不写死在代码里）；面向会用 API key 的技术型学习者。**Docker Compose 与“只监听 127.0.0.1”冲突**（容器内回环地址宿主机访问不到），若要支持 Docker 必须显式改 bind 并在文档写明这是安全取舍，不默认开启。桌面安装包不做 |

**角色与模型的分配**：

- 答案机：v0 用一个，目标三个异构。
- 挑错者：应当与主答案机不同厂商；只有一个厂商的 key 时仍可运行，降级为“同源提示”并警告；v1 起可并行调用多个异构模型。
- 提问者、出题者：独立会话，不读答案机对话，可与答案机用同一模型。
- 书记员：可共享上下文。

**异构性判定**：models.yaml 标注厂商与基座谱系，family 用列表表达（可标注多个谱系，另用 derived\_from 表达蒸馏关系），同厂商或蒸馏关系不算异构；不满足时警告，不拦截。异构只能降低错误相关性，不能消除。**统一口径（与风险表一致）**：目标是强制异构；只有一个厂商的 key 时工具仍可运行，但界面必须明示“本次挑错者与答案机同源，共识幻觉风险未降低”，且此时涉及关键卡点的单元不得自动闭环，需用户显式确认。

**失败与成本**：

- 角色可配置备选模型；失败时先自动重试，耗尽后提供一键切换，界面标明“本次使用备选模型”，不静默切换；每次调用的实际厂商和模型记入 llm\\\_call 表。
- 每次会话显示花费估算，设预算上限；接近上限时软提示，超过后需用户确认才继续。默认使用最低验证配置的原因是摩擦与成本，但**不是**论文估算的 4–5 倍——该倍数指多答案机并行的交叉验证，v0 只有一个答案机，不适用；v1 开启多答案机后才需要考虑。
- 全文检索比嵌入检索更容易漏掉同义表述，所以检索结果必须展示原文。

**适配层能力与协议**：适配层实现流式输出、失败重试与限流退避；价格表放在 models/pricing.yaml，由用户修改，因为厂商价格会变。项目采用 Apache-2.0 开源协议。

**模型版本**：配置中使用带版本号的固定模型 ID，不使用会自动指向新版本的别名；每次调用的实际模型 ID 记入 llm\\\_call，更换版本后重跑 test\\\_contracts。

**1. 模型适配与异构判定**

```python
```python
    # models/base.py
    from typing import Protocol
    from dataclasses import dataclass
    
    @dataclass
    class Msg:
      role: str      # "system" | "user" | "assistant"
      content: str
    
    @dataclass
    class Reply:
      text: str
      tokens_in: int
      tokens_out: int
      provider: str
      model: str
      finish_reason: str   # "stop" | "length" | ... 命中 max_tokens 时调用方必须重试或报错
    
    class Provider(Protocol):
      name: str
      supports_json: bool  # 是否支持结构化输出（json_object / tool calling）
      async def chat(self, messages: list[Msg], *, model: str,
                     temperature: float = 0.3, max_tokens: int = 1500,
                     response_format: str | None = None) -> Reply: ...
      # response_format 不可省：评分要点、缺口分级、挑错清单、概念图关系
      # 都依赖结构化输出，各家能力不同（Anthropic 无原生 json_object），
      # 由适配器声明 supports_json，不支持时退化为「解析 + 校验 + 重试」。
    
    # models/registry.py
    # models.yaml 示例（family 用列表，可标注多个谱系；derived_from 表达蒸馏）：
    #   gpt-x:      {provider: openai,    family: [openai]}
    #   claude-x:   {provider: anthropic, family: [anthropic]}
    #   gemini-x:   {provider: google,    family: [google]}
    #   deepseek-x: {provider: deepseek,  family: [deepseek], derived_from: [llama]}
    def heterogeneous(a: str, b: str, reg: dict) -> bool:
      if reg[a].get("provider") == reg[b].get("provider"):
          return False                                    # 同厂商
      fa, fb = set(reg[a].get("family", [])), set(reg[b].get("family", []))
      if fa & fb:
          return False                                    # 共享基座谱系
      da = set(reg[a].get("derived_from", []))
      db_ = set(reg[b].get("derived_from", []))
      if (da & fb) or (db_ & fa) or (da & db_):
          return False                                    # 蒸馏关系
      return True
    ```

**2. 角色契约与白名单组装器**（隔离的核心）

```python
```python
    # roles/contracts.py
    # allow 用元组而不是 set：set 的迭代顺序随进程启动的 hash 随机化而变，
    # 会让同一输入每次拼出不同顺序的 prompt，input_hash 不稳定、test_contracts 不可复现。
    CONTRACTS = {
      "questioner":      {"allow": ("learner_restatement", "concept")},
      "boundary_setter": {"allow": ("concept", "unit_title", "retrieved")},
      "critic":          {"allow": ("claim", "original_question")},
      "clerk":           {"allow": ("turn_text", "open_gaps")},
      "topic_picker":    {"allow": ("initial_belief", "ledger_summary",
                                    "difficulty_band", "retrieved")},
      "answer_machine":  {"allow": ("question", "retrieved", "unit_title")},
    }
    class ContractViolation(Exception): ...
    
    # roles/assembler.py
    def assemble(role: str, facts: dict) -> list[Msg]:
      allow = CONTRACTS[role]["allow"]            # 元组，顺序固定
      extra = set(facts) - set(allow)
      if extra:
          raise ContractViolation(f"{role} 不得读取：{sorted(extra)}")
      system = load_prompt(role)                  # prompts/.md
      body = render(role, {k: facts[k] for k in allow if k in facts})
      return [Msg("system", system), Msg("user", body)]

**3. 流程状态机与熔断**

```python
```python
    # engine/state.py —— 单元状态机（单元内）
    # LEARN → PRODUCE → VERIFY 是主干：PRODUCE 对应论文第 4 步
    # "回归主线（完成单元产出）"，验证必须在产出之后，不允许跳过。
    TRANSITIONS = {
    "INIT":      {"PICK"},
    "PICK":      {"LEARN"},
    "LEARN":     {"PRODUCE", "PICK"},    # PICK：熔断后降级重选（记 degraded_from / degrade_count）
    "PRODUCE":   {"VERIFY", "LEARN"},    # 产出（回归主线）；未完成则回到学习
    "VERIFY":    {"JUDGE", "LEARN"},     # 验证暴露缺口则回到学习
    "JUDGE":     {"INTEGRATE", "LEARN"}, # 用户判定未闭环则回补
    "INTEGRATE": {"PICK"},
    }
    def move(cur: str, nxt: str) -> str:
    if nxt not in TRANSITIONS[cur]:
        raise ValueError(f"非法转移 {cur} -> {nxt}")
    return nxt
    
    # engine/review_queue.py —— 延迟复测不进入上面的状态机
    # 它是跨单元的到期队列（2 / 7 / 21 天），由首页的到期检查直接消费：
    #   1) 不占用单元状态，用户不开始新单元也能做复测；
    #   2) 结果只写回被复测的 concept（verify_status / last_verified_at），
    #      绝不写入当前单元的账本，避免旧概念成绩污染当前单元；
    #   3) 复测完成后不转入任何单元状态，队列条目直接标记 done。
    REVIEW_INTERVALS = (2, 7, 21)  # 天
    def due_concepts(now, concepts):
    out = []
    for c in concepts:
        if c.last_verified_at is None:
            out.append(c)
        elif (now - c.last_verified_at).days >= next_interval(c):
            out.append(c)
    return out
    
    # engine/pacing.py
    def suggest_band(stats, cfg):
    """返回 ('up'|'hold'|'down', 依据)，仅为建议，用户可忽略。
    判定顺序严格按治理平面优先级：风险 > 质量 > 节奏 > 进度。
    原实现从节奏平面开始判，等于让节奏压过质量，且完全没有风险平面的输入。"""
    # 1) 风险平面（最先判定）
    if stats.unresolved_disagreement:
        return "down", "存在未裁决的实质分歧，先回退一手文献"
    if stats.unanimous_no_uncertainty:
        return "down", "多模型一致且无人标注不确定，视同分歧处理"
    if stats.isolated_node_ratio > cfg.isolated_max:
        return "down", "孤岛节点占比上升，先安排整合"
    if stats.skipped_produce_ratio > cfg.skipped_produce_max:   # 默认 0
        return "down", "连续跳过产出，先补齐单元产出"
    # 2) 质量平面
    if stats.pass_rate > cfg.pass_hi:                  # 默认 0.80
        return "up", "通过率高于目标区间"
    if stats.pass_rate &lt; cfg.pass_lo:                  # 默认 0.60
        return "down", "通过率低于目标区间"
    # 3) 节奏平面
    if stats.l1_gaps_in_session > cfg.l1_limit:        # 默认 5
        return "down", "一级缺口超过上限，触发熔断"
    if stats.zero_gap_ratio > cfg.zero_gap_max:        # 默认 0.20
        return "up", "零缺口会话占比偏高"
    # 4) 进度平面（优先级最低，仅在前三平面无信号时参考）
    if stats.gap_clear_ratio &lt; cfg.gap_clear_min:
        return "hold", "缺口清账率偏低，先清账再谈升降"
    return "hold", "处于目标区间"
    ```
```

**4. 计数型指标**

```python
```python
    # engine/counts.py
    from statistics import mean
    
    def pass_rate(attempts, threshold: float = 0.7, *, forced_unit_ids=None) -> float:
      """通过率。强行闭环的单元不计入——它们本就是「未达标」，
      若计入会直接污染 suggest_band 的升降判断。"""
      forced = forced_unit_ids or set()
      done = [a for a in attempts
              if a.confirmed_score is not None and a.unit_id not in forced]
      return sum(a.confirmed_score >= threshold for a in done) / len(done) if done else 0.0
    
    def calibration_gap(attempts) -> float:
      """自评与确认得分的平均差距；正值表示高估自己。"""
      pairs = [(a.self_score, a.confirmed_score) for a in attempts
               if a.self_score is not None and a.confirmed_score is not None]
      return mean(s - c for s, c in pairs) if pairs else 0.0
    
    def zero_gap_ratio(sessions) -> float:
      """零缺口会话占比。分母只算「候选缺口已确认」的会话：
      书记员的候选要用户确认后才入 gap，若把未确认的会话算进分母，
      用户「从不确认」会把该指标推高并误触发升难度——指标会被不作为操纵。"""
      confirmed = [s for s in sessions if s.gaps_confirmed]
      return sum(1 for s in confirmed if not s.gaps) / len(confirmed) if confirmed else 0.0
    ```
```

- 确认得分由用户对照评分要点后给出，取 0 到 1；通过阈值 0.7 是待校准参数。
- 延迟复测的结果权重高于当场作答。
- 以上全部指标的校准依据是本地日志与延迟复测结果，不引入 Elo 等评分模型（单人自用样本量达不到建模要求）。

      "llm_call":      {"id", "role", "provider", "model", "session_id", "unit_id",
                        "input_hash", "tokens_in", "tokens_out", "cost", "ts"},

      # audit_log 不在本白名单：只由 write() 在同一事务内追加，业务代码不得直接写；
      # chunk_fts 由检索索引器写入（v1），有独立的写入入口，同样不走本函数。
    }
    
    def write(db, table: str, row: dict, actor: str):
      allowed = TABLES[table]                 # 不在白名单里的表会抛 KeyError
      unknown = set(row) - allowed
      if unknown:
          raise ValueError(f"未知列：{sorted(unknown)}")
      cols = ", ".join(row)
      with db:                                # 同一事务：业务写入与审计要么都成功要么都回滚
          prev = db.execute(
              f"SELECT {cols} FROM {table} WHERE id = ?", (row.get("id"),)).fetchone()
          # 用 UPDATE / INSERT 而不是 REPLACE：REPLACE 实际是 DELETE + INSERT，
          # 会触发外键的删除语义，且删除动作本身不会进审计日志。
          if prev is None:
              marks = ", ".join("?" for _ in row)
              db.execute(f"INSERT INTO {table}({cols}) VALUES({marks})",
                         tuple(row.values()))
          else:
              sets = ", ".join(f"{c} = ?" for c in row if c != "id")
              db.execute(f"UPDATE {table} SET {sets} WHERE id = ?",
                         tuple(row[c] for c in row if c != "id") + (row["id"],))
          db.execute(
              "INSERT INTO audit_log(ts, actor, table_name, row_id, change, prev) "
              "VALUES(?,?,?,?,?,?)",
              (now(), actor, table, str(row.get("id")),
               json.dumps(row, ensure_ascii=False),
               json.dumps(dict(prev) if prev else None, ensure_ascii=False)))
          # prev 存旧值：第五节承诺"可借助审计日志撤销"，只存新值无法回滚。
    ```
```

- 用户的确认动作（闭环、分级、废弃）的 actor 为 user；书记员的候选缺口 actor 为 clerk，只写入 gap\\\_candidate，不写 gap。
- 表名和列名都来自 TABLES 白名单，不接受外部输入；拼接到 SQL 里的只有白名单内的名字，值一律用参数绑定。

**6. 本地服务的来源检查**

```python
```python
    # web/security.py
    ALLOWED_HOSTS = {f"127.0.0.1:{PORT}", f"localhost:{PORT}"}   # PORT 来自配置
    ALLOWED_ORIGINS = {f"http://127.0.0.1:{PORT}", f"http://localhost:{PORT}"}
    async def check_request(request):
      if request.headers.get("host") not in ALLOWED_HOSTS:      # 防 DNS 重绑定
          raise HTTPException(403, "Host 不被允许")
      if request.method not in ("GET", "HEAD"):
          if request.headers.get("origin") not in ALLOWED_ORIGINS:
              raise HTTPException(403, "来源不被允许")
          if not csrf_valid(request):
              raise HTTPException(403, "CSRF 令牌无效")
    
    def safe_path(root: Path, rel: str) -> Path:
      base = root.resolve()
      r = Path(rel)
      if r.is_absolute():
          # 必须挡在前面：pathlib 的 / 运算符遇到绝对路径会丢弃 base，
          # base / "/etc/passwd" 直接得到 Path("/etc/passwd")，
          # 此时后面的 parents 检查形同虚设。
          raise HTTPException(400, "路径越界")
      p = (base / r).resolve()          # 解析符号链接后再比较
      if p != base and base not in p.parents:
          raise HTTPException(400, "路径越界")
      return p
    ```
```

- 所有请求都校验 Host，所有写请求再校验 Origin 与 CSRF 令牌；挂载文件夹只读，safe\\\_path 拒绝路径穿越和指向挂载目录之外的符号链接。

## 十、开发路线与测试

开发分三个版本、八个里程碑，每个里程碑都有可检验的验收；隔离测试从 M3 起就要通过。分阶段的目的是尽早验证学习流程：每多一块没经过实际使用的功能，就多一块要维护的代码，所以顺序按验证价值排，不按工作量排。

| **版本** | **范围** |
| --- | --- |
| v0 | 多项目（每个项目独立数据库）；四本账；选题、答案机、提问者、出题者、书记员；**固定三问重述 + 边界题 + 提问者追问（追问提前进 v0，它不需要异构模型且成本不高）**；判分协议与闭环判据（含关键卡点例外）；用户判定；**产出（回归主线）步**；一个答案机加挑错者（有第二个厂商的 key 时为异构）；两种 Provider；预算提示与上限（M0–M5） |

**AI 辅助开发约定**：开发者只有一人，代码主要由 AI 生成，所以质量控制靠流程。

- 本文档就是给 AI 的规格说明：每个里程碑的“内容”和“验收”可以直接作为任务描述。
- 先写验收测试，再让 AI 实现，测试由你自己审阅；测试没写清楚的行为，AI 实现出来也不可信。

- 各厂商 API 的参数和行为以官方文档为准，不凭 AI 的记忆；依赖锁定版本。
- 单人维护的开源项目，对外的 issue 和合并请求要有明确的范围声明，避免被需求拖散。

## 十一、风险与限制

最大的风险是验证失效和未经验证的效果；下表列出主要风险及对策。

| **风险** | **影响** | **对策** |
| --- | --- | --- |
| 提问者或出题者读到答案机对话 | 追问退化为复述 AI 已说的话，验证失效 | 白名单组装器；隔离自动测试；输入预览 |
| 答案机或挑错者同源 | 共识幻觉，验证失效 | 目标是强制异构；只有一个厂商的 key 时仍可运行，但界面必须明示“本次挑错者与答案机同源，共识幻觉风险未降低”，且涉及关键卡点的单元不得自动闭环，需用户显式确认。分歧优先于投票 |
| **跳过产出直接验证** | 只检验到“解释层面的理解”，应用层面的理解从未被检验 | 产出步写入 unit；跳过则打标记、不计入完整进度、风险平面提醒 |
| 书记员越权 | AI 决定“你学会了没有” | 只建议；分级、废弃由用户确认，闭环由用户给出的确认得分决定 |
| 项目内记忆漂移 | 偏向性回答 | 四本账；用户确认写入；空白上下文模式 |
| 选题没有标准答案 | 学错方向，零基础者难以察觉 | 出处必填；用户可改题；标注“模型推断” |
| 评分要点有误或评分噪声 | 误判是否闭环 | 重述判据固定为三问、不由模型生成；边界题要点由用户自评并对照；确认得分由用户给出；差距记入 attempt |
| 强行闭环被滥用 | 进度虚高 | 必须填写理由；强行闭环不计入进度；指标单独显示 |
| 即时表现高估学习 | 优化了错误的指标 | 延迟复测；自评与确认得分的差距 |
| 用户敷衍作答 | 验证流于形式 | 折叠答案、字数提示、复测抽查；只能降低风险 |
| 数据发往云端厂商 | 隐私暴露 | 厂商白名单；明确提示；本地日志默认关闭 |
| 本地服务被其他网页或路径穿越利用 | 密钥或文件泄漏 | 仅监听 127.0.0.1；Host、Origin、CSRF 校验；挂载只读与路径校验；safe\_path 先拒绝绝对路径再比较 |
| 模型版本悄悄更新 | 角色行为漂移 | 固定带版本号的模型 ID；换版本后重跑 test\_contracts |
| 成本与延迟 | 用户放弃使用 | 分级验证；预算提示与上限 |
| 流程偏重，用户流失 | 放弃使用 | 默认最低验证配置；非必要步骤默认自动、批量或可忽略；先手动跑一遍流程再调整 |
| AI 生成代码的质量与可维护性 | 幻觉接口、未经测试的缺陷、难以维护 | 先写验收测试；小步提交；依赖锁定；关键模块人工评审 |

**效果验证**：开启后的本地日志用于校准参数；用延迟复测通过率做自我对照（本工具学的项目与常规方式学的项目）。**这是 n=1 的个案观察，不是对照实验**：无随机化、无对照组、样本极小，仅作个人参考，不得对外宣称有效，也不得写进 README 的效果说明。
